# BACKEND GUIDE

适用于整个 `backend/`，包括 `internal/`；同时遵循[仓库指南](../AGENTS.md)。Go 版本以 [go.mod](go.mod) 为准，接口领域与分组以 `.api` 中的 `@server` 声明为准。

## 关键入口
| 任务 | 位置 |
| --- | --- |
| 接口契约与分组 | [chasing_points.api](chasing_points.api) |
| 启动、手工路由与后台任务 | [chasing_points.go](chasing_points.go)、[wechat_message_push_route.go](wechat_message_push_route.go) |

| 数据结构与测试 schema | [migrations/](migrations/)、[internal/testsupport/](internal/testsupport/) |

## 契约生成
- `.api` 中 `service` 名保持 `chasing_points-api`。修改后下一步立即生成代码；在 `backend/` 执行：

```bash
goctl api go --api chasing_points.api --dir . --style go_zero --home ~/.goctl/default
```

- 执行前核对 goctl 版本与已有生成文件头，以及本机模板目录 `~/.goctl/default`；缺少生成条件时报告阻塞，不用手改生成文件代替。生成器或模板变更不要混入普通接口改动。
- 禁止手改标记 `Code generated by goctl. DO NOT EDIT.` 的文件，尤其 `internal/types/types.go`、`internal/handler/routes.go`。
- 新接口入口放在对应的 `logic/<group>/`；生成后补齐业务实现、handler 引用和测试，不提交 `todo` 空壳。检查生成 diff，避免无关改写。

## 分层与事务
- handler 只解析请求、调用 logic 和输出响应；业务编排、权限与领域规则放在 logic。管理端入口保持在 `handler/admin`、`logic/admin`。
- 新增查询、分页和聚合方法优先放 model。logic 可以编排跨模型事务，将同一个 `tx` 传给 model 方法；事务中的操作不能绕回非事务连接。
- 已有 logic 直接 SQL 不代表允许继续扩散，也不要求在无关任务中批量重构；需要调整时明确范围并补回归。
- `internal/logic/*.go` 根目录用于跨 group 共享 helper/service/protocol/payload，不新增 handler 一一对应的接口入口。
- 所有 DB、Redis、SMS、Push 等依赖从 `ServiceContext` 注入，不在 logic 中另建客户端。请求操作继承 HTTP Context（沿用 `svcCtx.WithContext(ctx)` 等现有方式）。
- 当前用户 ID 统一通过 `utils.GetUserIDFromCtx` 解析。WS 消息类型、连接参数与 [UniApp WebSocket 客户端](../uniapp/utils/websocket.js) 同步核对。

## 数据库与迁移
- 线上 schema 由 `migrations/*.sql` 管理，生产 model 构造函数禁止 `AutoMigrate`；表结构变更同步更新模型、json 字段与相关查询方法。
- SQL migration 包含 `+goose Up` / `+goose Down`，建表使用 `IF NOT EXISTS`。
- MySQL 不默认支持 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` / `DROP COLUMN IF EXISTS`。对已有表补删字段先检查 `information_schema.COLUMNS`，再按需执行兼容的 ALTER。
- 测试显式准备 schema，优先复用 `internal/testsupport`，不要依赖 model 构造函数建表。赛讯有效表为 `event_news_events`、`tournaments`、`tournament_matches`，不再使用旧阶段表或单表 `event_news`。
- `goose.sh` 从 `backend/.env` 读取数据库配置；运行前确认目标库。需要 MySQL 的集成/验收测试使用明确授权的隔离库。

## 读取与缓存边界
- GET/读取接口保持业务纯读，不隐式补数据、创建默认记录或执行全局状态收敛。
- 列表在数据库内分页、稳定排序并限制 `page_size`；禁止在线 `ListAll`、无界历史扫描、Go 内存分页及 N+1。
- 高频首屏优先复用聚合接口，保持固定、有界的 SQL 数量；可选区块失败返回 availability/partial error，不伪装成成功零值。
- 数据库与缓存操作继承真实请求 Context，确保 SQL、耗时与缓存结果进入请求完成观测。热点读取变更补 query-count 测试；索引变更用代表性 MySQL EXPLAIN 验证。
- 缓存由具体领域维护，明确 key scope、TTL 和失效时机；公共缓存不含 viewer 个性化数据，Redis 异常回源权威数据。
- 公开且可个性化的接口使用统一 optional JWT；无效 Bearer Token 返回 `401`，不得降级为匿名。
- 新读模型只在开关精确为 `enabled` 时启用；快照缺失时有界回退或明确 partial，默认不切读。

## 验证与运行
以下命令在 `backend/` 执行，按任务选择，不是连跑清单：

```bash
go test ./...
go build .

# 启动会连接外部服务并运行后台任务，先确认配置与授权；必须运行整个 package
go run . -f etc/chasing_points-api.yaml

# 仅在确认目标数据库后使用
./goose.sh status
./goose.sh up
```

创建迁移使用 `./goose.sh create <name>`。仓库根目录的 `make build` 用于 Linux amd64 部署构建，和本机编译不是同一个验证目标。
