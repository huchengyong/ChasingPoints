## Context

原生端已有 `SessionStore.authorizedRequest`（统一 401 刷新/一次重放，认证代次变化时抛出 `SessionError.changed`）和“我的”导航栈（资料卡、编辑昵称、设置）。UniApp 对应链路是 `subPages/user/matchHistory.vue` → `subPages/match/matchResult.vue`，两者仅作信息组织参考。

UniApp 存在两个容易混淆的“详情”页：

| 页面 | 接口 | 视角 | 入口 | 本期 |
| --- | --- | --- | --- | --- |
| `matchResult`（战报） | JWT `GET /api/match/detail` + `GET /api/match/reward-summary` | 我方视角 `my_*` / `opponent_*` | 对局记录、比赛结束、通知 | **迁移** |
| `matchDetail`（局记录/观战） | 公开 `GET /api/public/match/detail` + matchWS | P1/P2 中立视角，含每局 `rounds` | 观赛 Tab、交锋记录 | 不迁移 |

JWT 详情 DTO `MatchDetailData` 不含 `rounds`，公开 DTO 不含排位变化，因此“战报”与“局记录”的分界来自后端契约本身。

本期依赖的契约事实（以 `backend/chasing_points.api` 与当前逻辑为准）：

| 接口 | 关键事实 |
| --- | --- |
| `GET /api/match/list?page&page_size` | 读取 `match_participant_results`，只含已结算对局，按完成时间倒序；`result` 1=胜 2=负 3=平；`total` 用于判断是否还有更多 |
| `GET /api/match/referee/history?page&page_size` | 只含已完成（2）和已取消（3）的执裁对局，`page_size` 超出 1–100 时回落为 20；查询失败返回 HTTP 200 + `success: false` |
| `GET /api/match/detail?match_id` | 双方与裁判可读，其他人拒绝；返回我方视角比分、排位变化与明细、亮点/统计、裁判与完成方式；大量 `snooker_*`、`can_*` 实时计分字段 |
| `GET /api/match/reward-summary?match_id` | 未完成对局返回 `status: pending`；已完成返回 `ready` 与可能为空的奖励列表；对局不存在返回 `success: false` |

时间字段为带 `+08:00` 的 ISO 8601 字符串。

## Goals / Non-Goals

**Goals:**

- 已登录用户在原生“我的”回看参赛与执裁记录，进入只读战报。
- 建立可复用于后续列表页的原生分页读取模式：首次加载、刷新、加载更多、空/错误/刷新失败、迟到响应丢弃与身份隔离。
- 只解码战报所需字段，为后续对局链路提供基础的对局数据模型，但不提前定义实时计分状态。

**Non-Goals:**

- 继续执裁卡片、`getCurrentMatch`、再来一局、战绩海报、交锋记录、荣誉墙及 `matchDetail` 局记录/观战。
- WebSocket、实时刷新、比赛结束后自动失效列表（原生端尚无结束比赛入口）。
- 按球种/胜负筛选、段位/积分概览卡（`/api/user/overview` 另行迁移）。
- 修改后端契约、通用列表框架、本地持久化缓存或新依赖。

## Decisions

### 1. 范围以“列表 + 战报”闭合，出站入口全部不展示

战报底部的“生成战绩海报”“查看交锋记录”、奖励区的“前往荣誉墙”在 iOS 本期**不展示**，页面为纯展示；不使用“尚未开放”占位页，以免出现大量无效入口（与 P0 变更“不展示无效入口”的方向一致）。从历史进入时 UniApp 本就隐藏“再来一局”。后续迁移对应页面时再逐个恢复入口。

### 2. 已取消的执裁记录只展示、不可进入

执裁列表会返回已取消对局。它们没有有意义的战报（奖励接口对未完成对局永远返回 `pending`），因此列表行显示“已取消”标签与比分，不可点击、不显示进入箭头。已完成执裁记录进入战报的裁判视角。

### 3. 胜负平：列表用 `result`，战报按最终比分三分

列表直接使用服务端 `result`（1/2/3）。`MatchDetailData` 没有 `result` 字段，战报对已完成对局按 `my_score` 与 `opponent_score` 比较得出胜/负/平，相等即显示平局，修正 UniApp 战报把平局显示为“这场先记下”的问题。本期不为此修改 `.api` 契约；实施时先核对后端结算 `result` 与最终比分的关系，若存在不一致的结算路径（如认输、裁判判定），再单独提出契约变更，而不是在客户端猜测。

### 4. 读取模型只解码需要的字段

- 列表：`MatchHistoryItem`（参赛）与 `RefereeHistoryItem`（执裁）分别解码各自契约字段。
- 战报：`MatchReport` 只解码 id、`game_type`、`status`、`viewer_role`、双方姓名/头像/比分、胜率、排位变化与明细、`summary_highlights`、`summary_stats`、裁判字段、`completion_source`、`created_at`。实时计分字段不进入模型，留给对局链路迁移时定义。单杆最高在 UniApp 战报中只被定义、未展示，因此本期不解码。
- 业务包装 `success: false` 视为业务错误（沿用 `APIClient` 的既有判断），不展示空数据。
- 球种文案：1 斯诺克、2 九球追分、3 中式八球、4 美式九球，未知为“台球”；分差单位九球追分为“分”，其余为“局”。

### 5. 分页状态按分栏独立，身份变化整体重置

每个分栏持有独立状态：`items`、`page`、`total`、`phase`（idle/loading/loaded/empty/error）、`isRefreshing`、`isLoadingMore`、`refreshError`、`requestToken`。

- 首次进入页面只加载当前分栏（参赛）；切换到未加载过的分栏时才加载该分栏；从战报返回、分栏来回切换都**不**重新请求。刷新只通过下拉触发。
- 每页 20 条，`hasMore = items.count < total`；加载中、刷新中或没有更多时不发起加载更多；加载更多失败回退页码并保留已有数据，显示可重试提示。
- 刷新成功用第一页替换列表；刷新失败保留已有列表并显示刷新失败提示；首次加载失败显示整页错误与重试。
- 每次请求记录 `requestToken`，只有最新请求的结果能落地；同一分栏的旧请求结果丢弃。

身份隔离：`authorizedRequest` 已在认证代次变化时抛出 `SessionError.changed`，该错误静默丢弃。但已加载的列表可能跨越身份存活（页面仍在导航栈上），因此 `SessionStore` 需公开一个**只读**的当前身份值（用户 ID + 认证代次），不公开任何 setter。列表与战报记录发起请求时的身份，结果落地前再次比对；身份变化时清空两个分栏的数据与错误。会话失效或退出导致 `session.user == nil` 时，已推入的列表/战报改为显示登录引导，不继续展示旧数据。

### 6. 战报读取：详情与奖励各读一次、互不阻塞

- 进入战报时读取一次详情；失败显示整页错误与重试，**不**展示默认比分。
- 选手视角且对局已完成时额外读取一次奖励摘要：`ready` 且有列表时展示奖励；`ready` 空列表不展示奖励区；`pending` 显示“本场荣誉奖励仍在处理中”；失败只隐藏奖励区，不影响战报其余内容。从历史进入不需要 UniApp 面向刚结束比赛的 3 次轮询，本期不轮询。
- 裁判视角不读取奖励，隐藏排位变化、奖励与选手相关文案，展示双方选手与裁判卡、完成方式。
- 战报读取同样绑定身份；返回列表后再次进入同一战报允许重新读取（新页面实例），不做跨页面缓存。

### 7. 视觉与可访问性沿用原生规则

颜色走 `AppTheme`；UniApp 的亮点 tone（gold/blue/red/green 等十六进制色）映射到 `DESIGN.md` 的品牌与状态语义，而不是照搬十六进制值。胜/负/平标签同时使用文字，不只依赖颜色。头像沿用 `ProfileAvatar` 的占位策略（空值、无效地址、加载失败均显示占位），按列表与战报所需尺寸参数化。列表行合并为单个可访问元素，朗读对手、球种、结果、比分与时间。

## Risks / Trade-offs

- 战报按比分推断胜负平可能与服务端结算 `result` 不一致 → 实施前核对结算路径并补测试；如有分歧提出契约变更而不是在客户端写特例。
- 公开只读身份值扩大了 `SessionStore` 的读取面 → 只暴露不可变的值类型，不提供写入；补测试确认身份变化后旧页结果不落地。
- 列表不随比赛结束自动失效 → 原生端本期无结束比赛入口，依赖下拉刷新；对局链路迁移时再设计失效通知。
- 历史数据量大时持续加载更多 → 服务端分页已有上限，客户端不预取，只在滚动到底部时请求下一页。
- 时间格式依赖服务端 `+08:00` 字符串 → 解析失败显示“时间待同步”，不崩溃、不显示错误时间。

## Migration Plan

1. 在会话层公开只读身份值，补读取模型与夹具。
2. 实现分页读取状态与对局记录列表，在“我的”加入入口。
3. 实现战报页（选手/裁判视角、奖励摘要）。
4. 自动化测试、Debug/Release 构建、模拟器验收、开发账号只读联调，记录到 `docs/testing/`。

无数据或 Keychain 迁移；入口与页面可整体回退。

## Open Questions

以下三项已按探索阶段的推荐写成上面的默认决策，实施前如需调整可直接改本节与对应 Decision：

1. 战报出站入口：默认全部隐藏（Decision 1），备选为显示后进入“尚未开放”占位页。
2. 已取消执裁记录：默认展示但不可点击（Decision 2），备选为直接过滤。
3. 战报平局判定：默认按比分三分、不改契约（Decision 3），备选为给 `MatchDetailData` 增加 `result` 字段并跑 goctl。
