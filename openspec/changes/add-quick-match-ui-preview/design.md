## Context

依据 PRD V1.3、低保真 W1.3 和 DESIGN.md，交付纯预览，不实施约球 API。

## Goals / Non-Goals

**Goals:** 暖米白与金色视觉、双人联动、移动适配、可重复演示主路径和边界。

**Non-Goals:** 真实账户、持久化业务状态、后端鉴权、真实排位结算、应用页面改造。

## Decisions

- 使用原生 HTML/CSS/JS、本地资源；不用 Vue/构建工具，确保 file:// 和静态服务器均可打开。
- 一份内存中的模拟邀请列表，用户 A/B 共用数据、各自导航；不是两套互不关联的截图。
- 桌面双手机，手机切换角色；独立的预览控制台载入场景、调整模拟时间，与产品按钮隔离。
- 使用固定北京时间的演示时钟和可操作时间场景，清楚显示“模拟数据”；正式计分仅演示结束联动，不冒充生产规则。
- 原生按钮、表单、焦点反馈与弹层键盘操作；视图更新保持滚动和输入上下文。
- 结束改用原生 range 滑块：阻止轨道直接点到末端，仅从左端拖动至终点松手才完成；半途或触摸取消复位，保留键盘操作。任一参与者单方结束，不再模拟对方审批；实际服务端结束流程未修改。

## Risks / Trade-offs

- [模拟逻辑被误当作后端实现] → 页面和 README 明确范围，不调用 API、不修改应用代码。
- [file:// 限制] → 普通脚本与相对本地资源，不用 fetch 或 ES module 加载。
- [状态回归] → 一份 runnable 检查覆盖等待不建比赛、拒绝退出、合并替换、过期、结束同步及设置拦截；浏览器截图检查宽窄屏。
