## Why

熟人约球的 PRD V1.3、低保真 W1.3 和 HTML 交互预览已定稿，但当前 App 的「PK 挑战」只有回应和线下扫码开局，无法做到约好后双方各点一次直接开局；现有排位结束还要求对方确认。需要把已评审的流程实现为后端权威、双账号可恢复的真实功能，而不是复用预览的内存模拟。

## What Changes

- **BREAKING（未上线约球链路）**：将现有 `challenge` 邀约改为真实约球，发送时保存对手、球种、比赛类型、必要赛制、北京时间整点区间及次晨 07:00 失效时间；支持收到/发出、互邀合并、取消/拒绝/放弃、等待、过期及历史记录，不再使用发送后 24 小时失效或「已接受后再扫码」的约球流程。即时扫码开局仍保留原凭证校验。
- 服务端仅在两名本人分别主动进入同一有效约球后原子创建一场比赛；首人仅等待，退出等待不取消约球；比赛正常结束或取消时同步结束关联约球。任意一方可单方完成约球比赛的滑动结束，无需对方确认，但仍遵守球种/赛制的合法结束条件及既有结算逻辑。
- 为「对局」「我的」共享活动状态及收到邀请入口提供权威、可恢复的读取；接通约球记录、通知落点、等待页、比赛页滑动结束与对局详情的「再约一场」。
- 在「我的 → 设置」加入按账户保存的「仅允许好友约球」（默认关闭），由服务端按接收方实时设置与好友关系拦截新发送；不追溯关闭已有约球。

## Capabilities

### New Capabilities
- `quick-match-invites`: 约球发送/接受/等待/双方进入开赛/终态、好友限制、双入口及交互闭环。

### Modified Capabilities
- `pool-match-formats`: 约球创建的排位灵活赛制，在合法结束点单方完成结算，不进入双方结束确认；非约球比赛保持既有规则。
- `read-api-composition`: 用户 Bootstrap 纳入当前约球和待回应邀请摘要，供两个主 Tab 共用且保持部分可用语义。

## Impact

涉及 `backend/chasing_points.api`、`backend/migrations/`、`internal/model`、`internal/logic/challenge|match|user`、活动 Bootstrap、通知与 WS，以及 `app/api`、`app/store/activity.js`、对局/我的入口、约球与等待页面、设置和进行中/详情页面。需更新迁移、相关测试及双账号验收；仅清理开发/测试/本地的相关旧约球数据，不改 admin/website，也不将 `docs/previews/quick-match-ui/preview.js` 接入生产。
