## Context

原生工程目前由 `SessionStore.user` 发布登录/恢复后的资料，“我的”显示昵称和手机号，使用系统头像占位，并直接提供主题和退出按钮。UniApp 的 `pages/user/index.vue` 与 `subPages/user/editProfile.vue` 可提供信息组织参考。

本期可复用的真实契约：

| 接口 | 用途与边界 |
| --- | --- |
| `GET /api/user/info` | 现有会话恢复入口，返回顶层 `success`、`user_info` |
| `POST /api/user/profile` | JWT 认证；本期仅发 `nickname`，成功返回 `success`、`message`、完整 `user_info` |

资料字段为 `id`、`phone`、`nickname`、`avatar`、`status`、`created_at`；手机号由服务端脱敏，未绑定时为空。资料更新对昵称执行 `TrimSpace`，按 Go rune 校验 2–12 个字符；省略头像会保留服务端当前头像。HTTP 200 也可能带 `success: false`。

## Goals / Non-Goals

**Goals:**

- 完成原生资料展示、昵称编辑、返回后同步以及重启后读取新昵称。
- 复用会话和主题，保证退出/切号后的旧数据不会回写，普通页面切换不增加用户资料请求。
- 提供有清楚结果的保存、取消、错误重试和设置操作。

**Non-Goals:**

- 头像上传、手机号绑定/编辑、会员、战绩、段位和实时同步。
- 通用表单框架、用户缓存层、Bootstrap、后台轮询或新依赖。
- 修改后端契约或解决现有服务端整行更新的跨设备竞争。

## Decisions

### 1. 以现有会话用户作为单一资料来源

“我的”和编辑页从 `SessionStore.user` 取值，访客和恢复未成功时不开放昵称编辑。编辑页仅保存输入草稿；保存成功后用响应中的完整用户资料更新共享状态，随后返回“我的”。取消和失败不提前修改显示昵称。

不在资料卡、设置页和编辑页的 `onAppear` 新增无条件 GET。现有恢复读取结束后才允许编辑；本期不引入并行的资料刷新路径，从结构上避免保存前的旧读取覆盖新昵称。恢复重试继续走现有去重入口。若实施中新增读取入口，必须补充旧读取不能回滚已保存资料的验证。

### 2. 昵称提交只包含实际修改字段

选择 `POST /api/user/profile`，因为它已有 trim 语义且成功返回完整资料。另一个 `POST /api/user/nickname` 不做 trim，本期不同时维护两条写入路径。

提交前去除两端空白，按 `unicodeScalars.count` 对齐服务端 rune 数量，校验 2–12；空值、未修改或正在保存时不发请求。不要复制 UniApp 保存昵称时附带缓存头像的做法，JSON 请求体只有 `nickname`。保存期间禁用重复操作；失败保留输入、显示错误并允许重试。

请求通过 `SessionStore.authorizedRequest` 使用已有 401 刷新和一次重放机制。新增资料更新动作在共享会话层完成响应校验与回写，验证返回用户仍匹配发起时的用户 ID、认证代次及启用状态；不直接公开任意 `user` setter。退出或切号后迟到成功/失败均不能更改新用户资料、提示或导航。

写入成功但响应不完整时不发布猜测的本地成功结果，保留草稿并提示无法确认保存结果。用户重试提交同一昵称仍使用相同接口；不要隐式循环重试。

### 3. 页面拆分保持简单

- “我的”：资料卡、编辑昵称入口、设置入口；继续显示访客、恢复和失效状态。
- 昵称编辑：系统导航、单个输入框、取消/返回、保存与错误反馈。
- 设置：主题（跟随系统/浅色/深色）、用户协议、隐私政策、退出登录。访客也可使用主题和协议；已登录时显示退出，确认后复用现有 logout，回到访客页面，取消则保留会话。

远程头像用 SwiftUI 自带图片加载能力，限定显示尺寸，空值/无效地址/加载失败都展示占位图，不能阻塞资料卡。手机号原样显示服务端脱敏值，空值显示“未绑定手机号”，本期不给绑定入口。

主题沿用 `theme_mode` 和 `AppTheme`，承接 `DESIGN.md` 中品牌金、暖中性色、白色主按钮文字等品牌语义，布局使用原生尺寸与系统导航。协议复用现有 `https://www.zhuifen.cn/agreement` 和 `https://www.zhuifen.cn/privacy`，通过系统链接打开。

### 4. 验证以用户结果与请求行为为准

- 自动化覆盖昵称边界（中文、emoji/组合序列）、只提交 nickname、业务失败/网络失败、成功同步、迟到响应与账号隔离，以及无额外 GET。
- 保留认证测试的宿主隔离和独立 Keychain，自动化不访问真实账号。
- 模拟器人工验证三种主题、头像各种状态、保存/取消/返回、退出确认和登录恢复入口；记录实际运行版本。
- 专用开发账号验收一次真实昵称修改、返回同步、重启后恢复；记录结果并恢复测试前昵称。不能用本地模拟响应替代真实保存验收。

## Risks / Trade-offs

- Swift `String.count` 与 Go rune 对 emoji 的长度不同 → 使用 Unicode scalar 数量，并覆盖组合字符边界。
- 后端 `UserModel.Update` 目前采用整行保存 → 客户端省略头像可避免主动提交旧头像，但不宣称能够防止所有跨设备并发覆盖；服务端字段级更新另行处理。
- 已归档认证链路需要持续保持 → 本次会话方法扩展必须运行现有认证测试，保留环境隔离和 iOS 17.0。
- 真机与 iOS 17 运行验收尚无现成记录 → 在验证文档如实记录覆盖，正式发布前补齐，不将模拟器 18.1 通过写成全版本通过。

## Migration Plan

1. 补充昵称更新动作及其必要测试。
2. 在现有“我的”导航栈中增加资料编辑与设置页，迁移已有主题/退出入口。
3. 构建与回归后执行界面、开发后端验收，更新相应验证记录。

不需要数据或 Keychain 迁移；页面与更新动作可单独回退，认证存储格式保持现状。
