## Why

用户通常长期使用同一种球种，但当前每次发起 PK 都必须重新选择；同时斯诺克在扫码前强制选择预设总局数，增加了日常自由约球的操作成本。需要在保留现有发起 PK、扫码、对局模式和结算流程的前提下，记住用户的默认球种，并让斯诺克支持更贴近日常使用的自由局数与抢 N 局赛制。

## What Changes

- 新增按登录用户隔离的“默认对局类型”偏好；未设置时保持现有每次选择行为，设置后打开球种 Modal 自动预选默认球种。
- 保持“发起 PK”按钮、球种 Modal、扫码、对手匹配、练习赛/排位赛和公开范围等现有流程不变；本次临时改选其他球种不得覆盖默认偏好。
- 在设置页新增“对局偏好”区域，允许选择默认球种或“每次询问”；球种 Modal 同时提供明确的“设为默认”控制。
- 斯诺克新对局默认采用“自由局数”，不再在扫码前要求用户选择总局数；现阶段由系统提供内部初始击球方默认值，取消击球方概念不在本变更范围内。
- 在斯诺克进行中页面展示赛制项：默认显示“自由局数”，在尚未产生任何记分动作时可通过滚动数字选择器改为“抢 N 局制”。
- 抢 N 局制支持 N=1～25，任一方先达到 N 胜即满足正常结束条件，最多实际进行 49 局。
- 自由局数允许双方在至少完成一局且当前局已结算时主动结束整场，允许平局；完成第 49 局时系统强制进入正常结束流程。
- 普通对局和排位赛使用相同的自由局数/抢 N 局规则；排位赛仍保留现有双方结束确认与结算流程。
- 保留存量斯诺克对局和旧客户端的既有总局数语义，并为新赛制增加明确的数据、API、快照和 WebSocket 字段，避免复用含义不同的 `best_of_frames`。

## Capabilities

### New Capabilities
- `default-game-type-preference`: 定义默认球种偏好的设置、按用户持久化、Modal 预选、临时切换和清除行为。

### Modified Capabilities
- `snooker-rules-compliance`: 将新斯诺克对局赛制扩展为自由局数或抢 N 局，定义49局上限、允许平局、赛制锁定和普通/排位结束行为，同时保持存量规则兼容。

## Impact

- 移动端：`app/components/gameTypeModal.vue`、四个发起 PK 入口、`app/subPages/user/settings.vue`、`app/subPages/match/playing.vue`、斯诺克开局与赛制纯函数及对应测试。
- 后端契约：`backend/chasing_points.api` 的斯诺克创建、详情、同步快照和赛制更新接口；修改后需要立即运行 goctl 生成代码。
- 后端业务：斯诺克创建校验、动作结算、开始下一局、正常结束、排位结束确认、WebSocket 广播与历史兼容。
- 数据库：新增斯诺克赛制及目标胜局字段并迁移已有 `best_of_frames` 数据；Gorm 模型和前后端字段同步更新。
- 验证：移动端 `node --test tests/*.test.mjs` 与后端 `go test ./...`。
