## Context

WST 球员头像和赛事封面当前以 `https://images.gc.wstservices.co.uk/...` 形式写入数据库并由赛讯 API 原样返回。微信小程序会为网络请求附加不可修改的 `https://servicewechat.com/{appid}/{version}/page-frame.html` Referer，而该图片域的 CloudFront 会针对这一 Referer 返回 403。

移动端现有 `app/utils/image-cache.js` 仍通过 `uni.downloadFile` 请求同一来源，因此不能改变请求结果。后端已经通过 `internal/pkg/qiniu/UploadService` 管理七牛凭证、Bucket 和公开域名，但目前只签发用户头像的客户端上传凭证，没有服务端镜像能力。WST 自动同步和 `cmd/wst_sync` 已经提供持续同步及历史重跑入口，数据库中的球员头像和赛事封面也都是普通 URL 字段。

本变更跨越 WST 同步、七牛存储和移动端赛讯展示，但不需要改变 API 契约或数据库结构。所有图片处理均以已确认的内容使用授权为前提。

## Goals / Non-Goals

**Goals:**

- 在 WST 同步写库前，将球员头像和真实赛事封面镜像到自有七牛 CDN。
- 重复同步复用相同对象，不重复创建或覆盖同一来源图片。
- 镜像失败时保留已有自有 CDN 图片，并确保 WST 图片 URL 不再下发给小程序。
- 复用现有 URL 字段和同步命令完成历史数据回填。
- 使用应用自有默认图替代当前 WST 默认封面，并移除无效的客户端绕过逻辑。

**Non-Goals:**

- 不提供接受任意 URL 的图片代理或转存接口。
- 不镜像 WST 页面、视频、新闻正文图片或其他第三方资源。
- 不修改 `backend/chasing_points.api`、数据库 schema 或赛讯响应字段。
- 不建设通用媒体资产管理平台、图片编辑或动态裁剪服务。
- 不通过前端伪造、删除或修改微信固定 Referer。

## Decisions

### 1. 在 WST 同步阶段镜像，而不是运行时代理

球员和赛事源数据准备完成后、数据库事务开始前执行镜像。镜像成功得到的七牛公开 URL 再进入现有 `PlayerUpsertRecord` 和 `TournamentUpsertRecord`，事务内只负责数据库写入。

这样可以避免在数据库事务中持有外部网络请求，也让小程序、管理端和后续客户端直接共享稳定 URL。备选的运行时图片代理虽然改动入口较少，但会长期占用后端带宽、保留实时外部依赖并引入开放代理风险，因此不采用。客户端 `downloadFile` 方案因 Referer 不可修改也不采用。

### 2. 扩展现有七牛服务，能力保持窄化

在现有 `internal/pkg/qiniu/UploadService` 上增加服务端确保图片存在的能力；WST 同步通过一个仅包含该方法的小接口依赖它，以便使用 fake 编写同步测试，不新建通用存储框架。

服务端镜像只接受：

- HTTPS URL；
- 精确主机 `images.gc.wstservices.co.uk`；
- 声明为 `image/png`、JPEG（含 WST 使用的 `image/jpg` 别名）或 `image/webp` 的响应；
- 文件签名可识别为 PNG、JPEG 或 WebP，且 URL 扩展名与实际签名类型一致；
- 200 响应且大小不超过固定上限。

下载请求不设置 Referer，并使用明确超时和限长读取。WST 个别 JPEG 会错误声明为 `image/png`，因此最终上传 MIME 以文件签名为准；HTML、任意文件和不满足其他约束的来源仍按镜像失败处理，不允许调用方传入其他主机，从而避免形成 SSRF 或第三方转存入口。

### 3. 使用来源 URL 派生确定性对象键

对象键格式固定为：

- 球员头像：`wst/players/<source-url-sha256>.<ext>`
- 赛事封面：`wst/tournaments/<source-url-sha256>.<ext>`

同步先检查对象是否已经存在；存在时直接通过当前七牛公开域名拼出 URL，不重新下载或上传。不存在时才下载并上传。WST 图片使用 UUID 路径和 immutable 缓存语义，设计假定内容更新会产生新 URL；若来源 URL 改变，就自然生成新对象键。

### 4. 失败回退只保留自有资源

镜像结果按以下优先级写入：

1. 本次镜像成功的七牛 URL；
2. 数据库中已有且属于当前七牛公开域名的 URL；
3. 空值，由客户端使用应用内自有默认图。

已有 WST URL 或其他非受管远程 URL 不作为失败回退，以免继续向小程序下发已知不可用地址。公开赛讯响应映射再增加一道输出过滤：历史数据中若仍残留 WST 图片 URL，返回空值而不是原地址，确保分批回填期间也不会继续触发 403。球员无头像时继续使用现有本地默认头像规则；赛事无封面时使用新增的本地默认赛事封面。当前指向 WST 的前后端默认封面常量不再作为可持久化或可返回的默认值。

### 5. Dry-run 不产生存储副作用

`wst_sync --dry-run` 继续只统计候选记录，不检查、下载或上传七牛对象，也不修改数据库。正常同步才执行镜像；镜像调用全部发生在数据库事务之前。单张图片失败不终止整批业务数据同步，但必须记录包含资源类型和来源标识的错误日志，且不得记录七牛密钥或上传凭证。

选择单张失败降级而不是整批失败，是为了避免第三方单个损坏资源阻断赛事和比分同步。数据库写入本身仍保持现有事务语义。

### 6. 使用现有同步命令完成回填

不新增 migration 或专用回填程序。后端发布后，通过现有 `backend/cmd/wst_sync` 对需要保留的 WST 赛季执行完整非 dry-run 同步；同一路径同时覆盖后续自动同步。回填完成后检查官方球员和赛事记录，确保相关 URL 为当前七牛公开域名或空值。

### 7. 移动端直接消费自有 URL

赛讯详情继续使用现有字段渲染图片，但默认赛事封面改为包内静态资源。后端完成回填后，移除 `warmCachedPlayerAvatars` 及仅为该流程服务的 `app/utils/image-cache.js` 和测试，避免首次渲染仍发起 WST 请求及维护无效的双层缓存。

微信公众平台必须在发布前将七牛公开域名配置为下载合法域名。该配置是发布前置条件，但不改变代码中的运行时 URL 选择逻辑。

## Risks / Trade-offs

- [WST 图片使用授权不明确] → 在启用镜像和历史回填前确认授权；未确认时不得上线该能力。
- [首次历史同步需要下载较多图片，耗时增加] → 仅在非 dry-run 时执行，并通过确定性对象检查确保成本主要发生在首次回填。
- [七牛临时不可用导致新图片缺失] → 保留已有受管 URL；没有旧图时使用本地默认图，业务数据同步继续完成。
- [来源在同一 URL 下原地替换内容] → 当前依据 WST immutable/UUID 语义按 URL 去重；若后续观测到原地替换，再单独引入版本或 ETag，不在本次变更中预先复杂化。
- [微信后台遗漏合法域名配置] → 将真机 200 验证和合法域名检查列为发布任务，未完成不得发布移动端版本。
- [后端回滚后旧同步逻辑重新写回 WST URL] → 回滚后端前先停用 WST 自动同步；已有七牛对象和数据库 URL 保留，不做数据回滚。

## Migration Plan

1. 确认 WST 图片镜像授权、七牛配置和公开域名可用，并准备包内自有默认赛事封面。
2. 发布带受限镜像能力的后端；此时 API 和数据库结构不变，已有客户端可直接使用新的七牛 URL。
3. 使用现有 WST 同步命令按赛季执行完整同步，回填球员头像和赛事封面；核查数据库及赛讯 API 不再返回 WST 图片域名。
4. 在微信公众平台配置七牛公开域名为下载合法域名，并用体验版真机验证头像、封面和默认图。
5. 发布移除 WST 客户端缓存绕过逻辑的移动端版本。
6. 如需回滚，先关闭 WST 自动同步，再回滚后端或移动端；保留已镜像对象及数据库中的七牛 URL。
