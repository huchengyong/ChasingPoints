## Why

九球追分（game_type=2）按"总分"决胜负：普胜 +4、小金 +7、大金 +10、对手犯规 +1。底层数据记得没错，但整条读取与展示链路沿用了"按局"的模型：每次胜局被当成"一局"，详情页显示"总局数 / 当前局 / 局记录"，记分页显示"第 N 局"，复盘汇总"赢下局数"。用户真正关心的总分构成（各打出多少次普胜、小金、大金，各犯规多少次）反而看不全——结算总结只有本人的胜法次数，没有对手侧，也没有犯规；最后一次胜局之后的犯规计入了总分，却不出现在复盘里。

## What Changes

- 新增九球追分的**得分构成**读模型：从有效动作日志统计双方的总分、普胜 / 小金 / 大金次数、犯规次数与犯规送分，并给出按时间顺序的**得分明细流水**（每条：类型、得分方、分值、记分后的双方总分）。统计覆盖全部有效动作，包括最后一次胜局之后的犯规。
- 对局详情（参与者详情与公开详情）在九球追分时返回得分构成。
- 详情页：九球追分不再展示"总局数 / 当前局 / 局记录"，改为双方对照表 + 得分明细流水。
- 记分页：九球追分不再展示"第 N 局"。
- 结算页：九球追分展示双方对照表；总结条目不再只列本人胜法。
- 会员单场复盘：九球追分改为整场口径——整场得分走势、最大连续得分、双方胜法与犯规统计，不再返回"赢下局数"与逐局列表。
- 不改表结构，不改记分写入、撤销、排位结算与成就统计。其他球种行为不变。

## Capabilities

### New Capabilities

- `chasing-points-match-record`: 九球追分单场记录的读取口径——得分构成统计、得分明细流水、数据不一致与超长时的降级，以及详情页、记分页、结算页、复盘页按"总分 + 明细"而非"局"展示。

### Modified Capabilities

（无。九球追分复盘的现有口径定义在尚未归档的变更 `revamp-vip-benefits` 的 `member-benefits` 规格中，主规格里还没有；本变更在新 capability 中定义九球追分复盘口径，并在实现时同步修订该变更中的对应条目，见 design。）

## Impact

- **后端契约**：`backend/chasing_points.api` 新增得分构成相关类型；`MatchDetailData`、`PublicMatchDetailData`、会员复盘响应新增可选字段。均为新增可选字段，旧客户端不受影响。修改后需运行 goctl 重新生成。
- **后端逻辑**：`internal/logic/` 下的对局总结（`match_summary_helper.go`）、复盘（`match_replay.go`）、参与者详情与公开详情组装；新增一个共享的得分构成构建函数及其测试。
- **UniApp**：`subPages/match/playing.vue`、`matchDetail.vue`、`matchResult.vue`、`matchReplay.vue`，`utils/match-detail.js`、`utils/member-replay-view.js` 及对应测试。
- **原生 iOS**：目前不面向用户，本次不适配。战报页只渲染服务端下发的总结条目，条目调整后其中不再有本人普胜 / 小金 / 大金次数；得分构成展示留到 iOS 完整版开发时接入。
- **管理后台 / 官网**：不涉及。
- **数据库**：无迁移。
