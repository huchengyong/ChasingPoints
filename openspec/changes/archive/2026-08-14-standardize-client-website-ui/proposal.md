## Why

官网与 App/小程序已经共享金色品牌方向，但客户端仍混用暖金与冷蓝灰视觉体系，官网和客户端也缺少共同的颜色、圆角、间距、排版与组件状态标准。现在需要在不重做信息架构和业务交互的前提下，将现有视觉语言沉淀为可执行规范，并让公开用户界面稳定呈现为同一个品牌。

## What Changes

- 新增仓库级 `DESIGN.md`，作为官网与 App/小程序客户端的统一 UI 标准，明确适用范围、品牌原则、语义色、亮暗主题、排版、间距、圆角、阴影、按钮、卡片、表单、标签、弹层、空态、加载态和可访问性规则。
- 以现有“金色品牌、绿色语义、暖中性表面”为基础，建立语义化设计 Token，并分别映射到 UniApp 与 Nuxt 的现有样式入口；不引入跨运行时 UI 框架。
- 收口 App/小程序高频页面及仍使用冷蓝黑旧主题的子页面，使页面背景、卡片、文字、边框、主操作和状态色遵循统一语义。
- 收口官网重复硬编码的品牌色、表面色、圆角和按钮样式，使官网组件与统一标准保持一致。
- 建立轻量级静态检查和现有测试扩展，防止重新引入未经批准的品牌色、旧冷色暗面或绕过主题入口的页面样式。
- 保留平台必要差异：App/小程序继续使用同一 UniApp 页面体系，官网保持 Web 响应式布局；不要求两端共享组件代码或像素级完全相同。
- 明确排除管理后台、业务流程重构、页面信息架构重做、后端/API 变更和新增官网深色模式。

## Capabilities

### New Capabilities
- `public-ui-standardization`: 定义官网与 App/小程序统一的公开用户界面规范、语义 Token、组件状态要求、平台映射和页面一致性验收规则。

### Modified Capabilities
- 无。

## Impact

- 规范文档：新增仓库级 `DESIGN.md`。
- App/小程序：影响 `app/theme.json`、`app/App.vue`、`app/uni.scss`、主题工具、共享组件以及 `app/pages/`、`app/subPages/` 中需要收口的样式。
- 官网：影响 `website/assets/styles/main.css`、官网共享组件和少量页面局部样式。
- 测试：扩展 `app/tests/` 的主题契约检查，并为官网增加必要的样式契约测试。
- 不影响 `backend/`、API 契约、数据库、管理后台或业务数据模型。
