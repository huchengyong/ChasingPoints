## Why

中式八球和美式九球当前虽然按局记录胜负，但没有明确的赛制、目标胜局和服务端结束约束，用户只能在任意比分手动结束。需要将斯诺克已经验证过的“自由局数 / 抢 N 局”体验扩展到这两个逐局胜负球种，并由服务端保证局数上限、自动结束、排位确认和旧对局兼容。

## What Changes

- 为中式八球和美式九球新增独立于斯诺克的灵活赛制：`free`（自由局数）和 `race_to`（抢 N 局）。
- 新对局默认使用自由局数；创建者可在第一条记分动作前改为抢 N 局，目标胜局支持 N=1～65。
- 自由局数允许在至少完成一局后正常结束并允许平局；最多完成129局，第129局后自动进入正常结束流程。
- 抢 N 局以任一方先达到 N 胜为正常结束条件；N 最大65，因此最多实际进行129局。
- 练习赛满足正常结束条件后直接结算；排位赛继续进入现有双方结束确认流程，平局沿用现有平局结算语义。
- 新灵活赛制对局只允许通过“结束一局”记录一局胜负，每局固定计1胜；服务端拒绝通用加分或犯规接口绕过目标胜局和局数上限。
- API、当前对局、详情、同步快照和 WebSocket 统一返回赛制、目标胜局和当前用户是否可修改赛制。
- 保留存量中式八球、美式九球对局和旧客户端的既有手动结束行为；九球追分不纳入本变更。

## Capabilities

### New Capabilities
- `pool-match-formats`: 定义中式八球和美式九球的自由局数、抢1～65局、129局上限、赛制锁定、自动结束、排位确认及旧对局兼容行为。

### Modified Capabilities

无。

## Impact

- 移动端：`app/subPages/match/playing.vue`、`app/api/match.js`、开局 payload、通用赛制纯函数及对应测试；沿用创建后、首局前修改的交互，不扩展球种 Modal。
- 后端契约：`backend/chasing_points.api` 的创建、详情、快照、WebSocket 字段及通用赛制更新接口；修改后需要立即运行 goctl。
- 后端业务：创建校验、赛制更新权限、单局结算、目标达成后的正常结束、排位确认、通用写分绕过保护和实时广播。
- 数据库：为中式八球和美式九球新增通用赛制与目标胜局字段，并保持存量记录为 legacy。
- 验证：移动端 `node --test tests/*.test.mjs` 与后端 `go test ./...`，重点覆盖抢1/10/65、自由局数平局、129局上限和旧客户端兼容。
