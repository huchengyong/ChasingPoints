## Why

后台接口靠 JWT 保护，但管理员令牌和用户令牌用同一个密钥签发，只靠令牌里的 ID 正负区分（管理员是负数）。全局中间件对管理员 ID 原样放行，对正数 ID 只检查“用户存在且启用”，没有任何一层要求 `/api/admin/*` 必须是管理员。

结果是身份校验只能靠每个后台 logic 自己调用 `GetAdminIDFromCtx`，而这个检查已经漏了：39 个带 JWT 的后台接口里，有 20 个没有校验，任何登录的普通用户拿自己的令牌就能调用。受影响的包括用户列表、封禁/解封用户、球馆审核、球馆奖励配置、会员/信誉/大模型配置的读写、仪表盘、对局列表、社区帖子与反馈列表。这是需要尽快关闭的越权问题。

继续逐个补检查治标不治本：新增的后台接口只要忘一次就会再漏。需要一个按路径兜底、新增接口默认受保护的统一关口。

## What Changes

- 新增全局中间件：凡是 `/api/admin/` 下的请求，必须带管理员身份（令牌里的用户 ID 为负数）。
  - 带普通用户令牌：返回 HTTP 403，不进入任何 handler。
  - 没有身份：返回 HTTP 401。
  - 管理员令牌：行为不变。
- 公开入口不受影响：`/api/admin/login`、`/api/admin/init`、`/api/admin/exists` 继续允许匿名访问；即使请求头里带着过期的普通用户令牌，这三个入口也照常工作。
- 路径判断与 go-zero 路由器一致（先做 `path.Clean`），`/api//admin/...`、`/api/admin/./...` 这类写法不能绕过。
- 新增后台接口默认受保护，不需要在 logic 里重复写检查；公开入口只能显式加入白名单。
- 已有 logic 里的管理员检查保留，不做清理；它们仍用于取得操作人 ID。
- 新增回归测试：启动真实的 go-zero 服务，遍历注册的所有 `/api/admin` 路由，逐一验证普通用户令牌被拒绝。

不在本期：管理员令牌的吊销与改密后失效（当前令牌不查库）、管理员角色细分、后台操作审计。

## Capabilities

### New Capabilities
- `admin-api-access`: 后台接口的访问控制——哪些路径要求管理员身份、拒绝时的状态码、公开入口白名单、路径规范化。

### Modified Capabilities

（无）`gear-catalog` 中“后台接口逐一校验管理员身份”的要求继续成立，本变更只是在其之上增加统一关口。

## Impact

- 后端：新增 `backend/internal/middleware/` 中的后台访问控制中间件；`backend/chasing_points.go` 注册中间件（把全局中间件注册抽成函数以便测试）。不改 `.api`，不需要重新生成代码，不改表结构。
- 管理后台前端：无需改动。前端已把 403 显示为“没有权限访问”且不会登出。
- UniApp、原生 iOS、官网：不调用 `/api/admin`，不受影响。
- 部署：只需发布后端；先发开发环境验证，再发生产。
