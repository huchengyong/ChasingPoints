## Why

[PRD V1.4](../../../docs/prd/familiar-player-quick-start.md) 允许约球对局由任一参赛方单方滑动结束，但已按 V1.3 实现的排位结算在结束事务中立即生效。被结束的一方没有任何申诉途径；现有 `DisputeFinishMatch` 只对「结束请求」提异议，依附双方确认窗口，约球对局已不进入该窗口。排位分公开且影响赛季，需要在不恢复「等待对方确认」的前提下补上申诉途径。

## What Changes

- 约球排位比赛由一名参赛方手动结束（滑动结束）后：对局与约球照常立即完成，双方立即看到赛果、可以再约；**排位结算延后 10 分钟生效**，期间另一参赛方可提出一次异议。
- 异议成立后本场**不计排位积分**：不写段位变更、不计入排位口径的竞技统计与赛季记录；比分、胜负和对局记录保留，对局不恢复、约球不重开。
- 异议期结束未提出异议时，由后台任务按生效时刻完成排位结算，不依赖任何人打开页面；读取接口保持纯读，未完成结算时如实显示「待生效」而非伪造分数。
- 新增「对约球排位结果提出异议」接口；当前对局、对局详情和同步快照返回结束方、排位结算状态、生效时刻和是否可提出异议。
- 被结束的一方收到「X 结束了对局 · 比分」通知；App 赛果页展示异议入口与结算状态，原生 iOS 战报展示「待生效 / 不计排位积分」，不再把未结算显示成 0 分变化。
- 赛制达标自动结束、裁判结束、认输、练习对局、非约球比赛均不设异议期，沿用现有流程；非约球排位的双方确认与 `DisputeFinishMatch` 不变。

## Capabilities

### New Capabilities
- `quick-match-ranked-dispute`: 约球排位单方结束后的延后结算、限时异议、作废口径以及各端的结束方与结算状态展示。

### Modified Capabilities
- `pool-match-formats`: 「练习赛与排位赛使用各自既有结束流程」中约球排位手动结束改为对局立即完成、排位结算在异议期结束后生效（以 `implement-quick-match-invites` 归档后的条文为基线）。
- `competitive-read-models`: 「当前赛季记录必须随比赛结算更新」补充延后生效的排位以生效时刻归属赛季，作废比赛不更新赛季记录。

## Impact

- **后端**：`matches` 增加排位结算状态与生效时刻字段（goose 迁移 + Gorm 模型）；`FinishMatchLogic` 拆分「完成对局」与「排位结算」；新增到期结算 worker；新增异议接口并修改 `backend/chasing_points.api` 后运行 goctl；竞技读模型投影支持延后应用与作废；通知在事务提交后发送。
- **UniApp**：`subPages/match/matchResult.vue` 与相关 `api/match.js` 门面展示结束方、结算状态、生效时刻与异议入口；`playing.vue` 滑块说明写明结算与异议期。
- **原生 iOS**：`MatchHistoryModels.swift` / `MatchReportView.swift` 解码并展示结算状态，不提供异议操作。
- **依赖与顺序**：建立在 `implement-quick-match-invites` 之上，须在其归档后归档；不改 HTML 预览实现（PRD、线框图与预览已在 V1.4 / W1.4 同步）。
- 不涉及管理后台、官网；项目未上线，无存量数据转换。
