# PRD｜熟人约球与一键进入

> 版本：V1.3，结束对局改为单方滑动完成，无需对方同意。文档和HTML原型已调整，不代表App/后端已实现。
> 配套：[低保真原型 W1.3](./familiar-player-quick-start-wireframes.md) · [可点击高保真 HTML 预览](../previews/quick-match-ui/index.html)（仅模拟数据）。
> 无待确认产品项；第8节为实施注意事项，不新增业务规则。

## 1. 要解决的问题

两个人已经认识，也想一起打球。提前在 App 选好对手、球种和大概时间，见面后直接进入，不再扫码和重复选类型。

**第一人进入只是等待；第二人点击进入，才正式创建比赛。对方放弃，则结束约球，不产生比赛数据。**

```text
发起 → 对方接受 → 一人进入等待
                       ├─ 另一人进入 → 正式比赛 → 赛果 → 再约
                       ├─ 退出等待 → 保留约球，稍后再进入
                       └─ 取消 / 对方放弃 / 过期 → 约球结束，无比赛
```

不做找陌生人、聊天、订台、多约球排期、到场核验或新的审批系统；先沿用现有 UI 与比赛能力。

## 2. 核心规则

1. “对局”和“我的”展示同一条约球，都能直接处理。
2. 收到未回应邀请可以暂不处理，不影响发起自己的约球；自己发出的邀请尚未得到回应且仍有效时，必须先取消，才能换人发起。接受别人的邀请按第3节处理：同一人且同一类型的互邀合并，类型不同不直接匹配；不同人则提醒后自动关闭自己未被回应的旧邀请。双方一旦约好，本次约球结束前不能再发起或接受其他约球。
3. 时间只选 `今天 / 明天 / 后天` 和 `HH点到HH点`，不用日历、分钟秒。
4. 时间仅作提醒：早于开始时间且对方尚未进入时，先进入的人看到一次提示；对方已经在等待，则直接进入，不重复提示。到达开始时间后、约球未过期也直接进入，包括晚于预计结束时间。
5. 约球在**预计结束日期的次日早晨 07:00**失效。
6. 只保留这一个失效时间，不再增加单独的等待倒计时。
7. 接受和第一人进入均不创建比赛、不允许记分、不占双方的正式比赛资格。
8. 第二人主动进入成功后，双方进入同一场正式比赛，不再额外批准开局。
9. 放弃成功后约球结束，等待方退出等待页，不产生比赛、胜负、积分或处罚。
10. 返回页面与退出等待分开；只有本人点击进入才算进入，查看通知或 App 上线不算。
11. 关联对局正式结束后，同步结束本次约球，双方可以继续下一次约球，无需再手动取消。
12. 设置中的“仅允许好友约球”默认关闭。开启后，非好友不能向本人新发送约球邀请；按接收方设置判断。

## 3. 发起与接受

### 发起

- 选择明确的平台对手，不可选自己或无效账号；头像、昵称及必要身份信息帮助区分同名用户。
- 好友和最近对手都能选择，默认不要求最近对手先加好友；如果接收方开启“仅允许好友约球”，非好友不能向其新发送邀请，最近对手也不例外。前后端规则保持一致。
- 球种沿用用户偏好或入口上下文；从“再约一场”进入时带入对手和球种。
- 约球时可以选择比赛类型（如排位、练习），双方进入后直接沿用。接收方接受前能看到选择结果；开局不重新询问，也不因入口不同而改变类型。可见性与必要赛制沿用该类型的现有规则，在发送前确定并展示。
- 附言可选，不要求地点。已接受后要改类型或时间，首版取消重约即可。
- 发送成功展示现有约球，不要求再点“是否查看记录”。失败保留输入，结果不确定先查是否成功，不盲目重发。

### 时间输入

```text
预计什么时候打？
[今天] [明天] [后天]
    [16点] 到 [17点]
预计时间仅作提醒，不限制比赛时长
```

时间规则已确定：
- 同一天的整点区间，结束晚于开始；可使用 24 点表示当天结束，不开放自由跨日排期。
- 今天23点—24点仍在明天07:00失效，不能因存储成次日00:00而多延一天。
- 默认下一个可用整点和一小时区间；当天没有可用区间则展示明天，发送前清楚可见。
- 新建不可选完全过去的区间；相对日期发送时固定，跨午夜编辑时重新检查，不静默滚动日期。
- 统一按北京时间（Asia/Shanghai）解释“今天”和“次晨07:00”，以服务器时间判断，不能受手机改时间或时区影响。

### 跨午夜的日期展示

保存实际日期，显示时按当前北京时间转换“今天、明天、昨天”，不能把发起时的相对文案固定保存。

以8月25日16—17点、26日07:00失效的未开局约球为例：

| 查看时间 | 预计时间 | 失效提示/状态 |
| --- | --- | --- |
| 25日晚上 | 今天16点—17点 | 明天早晨7点失效 |
| 26日00:00—06:59 | 昨天16点—17点 | 今天早晨7点失效 |
| 26日07:00起 | 昨天16点—17点 | 已失效 |

- 失效后只显示“已失效”，不追加具体失效日期、时刻或长句，不重复显示同一状态。
- 页面一直打开时跨午夜也刷新日期文案；锁屏、切后台回来后重新计算。实际预约日期和失效时刻不变。
- 更早的记录用简洁月日，跨年带年份，避免歧义；日期展示覆盖两页卡片、收到列表和记录详情。
- 到07:00不仅更新文案，还按既定规则拒绝接受/进入；已正式开始的比赛不因约球时间而被标为失效。

### 接受与拒绝

接收人看到对手、类型、预计时间、失效时间，选择 `接受约球 / 这次不了`。

- 接受：双方显示已接受，不自动进入等待，不创建比赛。
- 拒绝：约球结束，告知发起人，不要求填写理由。
- 发起人可取消待回应邀约；接受后、未正式开局时双方均可取消。

### 收到与发出的邀请分别处理

| 当前情况 | 能否发起新的约球 |
| --- | --- |
| 只有别人发来、自己尚未回应的邀请 | 可以，无需先拒绝；旧邀请继续保留至处理或过期 |
| 自己发出一条邀请，对方还未回应且未过期 | 不可以；先取消自己的旧邀请，再换人发起 |
| 自己发出的旧邀请被拒绝、已取消或已过期 | 可以重新发起 |
| 已有双方接受且尚未结束的约球，包括等待中和由它开始的比赛 | 不再额外发起；收到待回应邀请不等于已接受 |

- 可以收到多条邀请，这不是安排多场已接受的约球；不能为了限制自己发起数量而阻止接收或强迫用户回应。
- 发送时不能仅因为对方有未回应的收到邀请而拒绝发送。
- 同时点击或多设备发送，也不能产生两条自己发出的有效未回应邀请。
- 自己发出的邀请未回应时，提示“你发出的约球还在等待回应，请先处理”，提供查看与取消，不自动取消或自动改约。
- 暂不回应没有额外操作，不要求点击“忽略”；也不自动拒绝别人。

### 点击接受时怎么处理（已确认）

| 自己当前的情况 | 点击接受收到的邀请 |
| --- | --- |
| 没有已约好的球，也没有自己挂着的邀请 | 直接接受，双方显示已接受 |
| 自己发给B的邀请未回应，同时收到B的同类型邀请 | 直接匹配为同一次约球，时间不同也能匹配；双方只显示一条已接受记录，不额外询问是否取消，也不立即创建比赛 |
| 同一人互邀，但类型不同 | 不直接匹配、不改类型、不自动关闭任一邀请；提示类型不同。用户可先取消自己未回应的邀请，再按普通流程接受收到的邀请 |
| 自己发给B的邀请未回应，收到的是C的邀请 | 提醒“接受后会自动关闭已发出的邀请”；确认后接受C并关闭发给B的邀请，取消提示则什么都不变 |
| 自己发出的邀请已经被对方接受，或自己已经接受了一次约球，且本次尚未结束 | 不能再接受其他邀请，提示“你已有未结束的约球，请先处理当前约球”，提供查看入口 |
| 点到的是同一条已经接受或合并过的邀请 | 展示现有约球，不创建第二条；这不是接受一场新的约球 |

- “已回应”中只有接受代表约好了；拒绝、取消或过期不阻止接受新的邀请。
- 只有同一人且同类型才能直接匹配，不能把不同球种或排位/练习等不同比赛类型当成相同。时间不同不阻止匹配，但参与匹配的邀请都必须仍有效。
- 匹配后两条原邀请指向同一次约球，旧卡片和通知都进入同一记录，不留下另一条可接受的重复邀请。
- 时间不同时，沿用本次点击接受的邀请所展示的时间，并按它计算次晨07:00失效时间；双方匹配后的卡片显示同一份信息，不取两段时间的交集，也不增加选时间步骤。其他开局信息沿用该邀请，不混合字段。
- 接受C并关闭发给B的邀请必须一起成功；若C的邀请失效、已取消或对方已有未结束约球，不能先关闭给B的邀请再报接受失败。
- 旧邀请关闭后告知B“对方已取消本次邀请”，不披露新约球对象；B的旧通知和卡片不能继续接受。其他收到但未回应的邀请不自动拒绝。
- 双方同时接受互邀，只形成一次约球；若各自选中了不同内容，首次成功接受的结果固定，另一个请求显示最终内容，不能再次覆盖。
- 接受前重新检查双方状态。若B恰好已接受了自己原先发出的邀请，则不能再切换去接受C；提示已有约球，保留成功的那次结果。
- 已接受、等待中以及由该约球开始的正式比赛，都算本次尚未结束。退出等待不代表约球结束；正式比赛开始后也不能借次晨07:00到期提前解除这条限制。
- 约球在开局前取消、放弃或过期，或关联比赛按现有规则结束后，才可以接受下一次约球。收到新邀请本身仍可不回应。

## 4. 进入、等待与开始

### 第一人进入

两人已接受、约球未过期时，任意一方都可先进入，不固定发起人。

- 提前进入：一次提示“预计明天16点开始，现在进入吗？”，取消提示不取消约球。
- 到达或晚于预计时间：直接进入。
- 等待页显示自己“已进入”、对方“待进入”；不显示0:0、正式比赛计时或记分按钮。
- 只保存约球和必要的操作/通知记录，不提前生成比赛ID、回合或比分。

### 第二人选择

在“对局”“我的”或通知落点直接看到：

```text
小李已进入，等你一起开始
中式八球 · 今天16点—17点
[进入对局]    [放弃本次约球]
```

- 进入：检查对方仍在等待、约球未结束/过期、双方没有冲突比赛后，创建唯一比赛。
- 对方已经在等待时，直接进入并正式开始，即使还没到预计时间也不再提示。若对方刚退出等待，自己成为先进入的人，仍按当前时间判断是否提示；以实际等待状态为准，不按发起人或接收人身份判断。
- 放弃：一次轻确认后结束本次约球。A在等待页则提示并自动退出；A在其他页面只更新提醒，不强行跳页；离线恢复时显示最新结果。
- 如果A已经退出等待，B点击进入后成为等待方，不能用A旧页面状态直接开局。

### 返回、退出等待、取消的区别

| 操作 | 结果 |
| --- | --- |
| 普通返回、系统返回、手势返回 | 只离开页面，继续等待；主页面显示“你已进入，等待对方” |
| 返回等待页面 | 恢复页面，不重新进入，不重复提前提示 |
| 退出等待，保留约球 | 本人变回待进入；约球保留，可稍后再进 |
| 取消本次约球 / 对方放弃 | 约球结束，需要重新邀约才能再打 |

锁屏、切后台或短暂断网不会自动退出等待。页面明确提示“返回或锁屏后仍会等待；暂时不打可退出等待”。因此，**已主动进入的人即使不在当前页面，对方进入仍可以正式开局**；这与只接受过约球、从未进入不同。

等待不另设时限，持续到本人退出、取消/拒绝、约球到次晨07:00失效、转去开始其他比赛，或双方正式开始。

## 5. 双入口与记录

| 入口/状态 | 展示与操作 |
| --- | --- |
| 对局页 | 首屏显示当前约球或比赛；无约球时保留原扫码等即时开局优先级，约球只是补充 |
| 我的 | 原status-card位置显示同一记录，不重排整个个人页 |
| 我发出待回应 | 等待对方回应，可取消 |
| 我收到待回应 | 接受 / 这次不了；可不处理。接受执行第3节分支，不直接覆盖现有约球 |
| 已接受、无人进入 | 进入对局 / 取消约球 |
| 我已进入 | 返回等待页面 / 退出等待 / 取消约球 |
| 对方已进入 | 进入对局 / 放弃本次约球 |
| 已正式开始 | 继续同一场比赛，正式比赛优先展示 |
| 无比赛无约球 | 普通开局入口，不贴虚构的“待开局”标签 |

对局页始终保留 `约球记录` 入口。活动卡消失后仍可查取消、拒绝、失效原因及赛果，并重新约同一人；复用已有记录页，不新建历史中心。

收到的待回应邀请不能挤掉自己正在处理的约球。当前比赛、已接受/等待中的约球、自己发出的待回应邀请优先展示；另以“收到的邀请”入口查看未处理邀请。只有收到邀请时，仍保留发起入口，多条邀请在现有列表中查看，不新增排期功能。

通知携带具体约球标识，打开显示最新记录，不自动进入。正常已登录冷启动落在其他主Tab时，`对局 → 进入`即可，不必搜索或翻历史。

### 设置：仅允许好友约球

入口：`我的 → 设置`，在现有“隐藏战绩”附近增加开关，不新增设置子页。

- 名称：`仅允许好友约球`；说明：`开启后，非好友无法向你发送约球邀请`。
- 默认关闭，按用户账号保存；重新登录、更换设备后保持。读取失败不能假装开关关闭，保存失败恢复原值并允许重试。
- 开启后仍允许好友发送；关闭后恢复现有好友和最近对手的发送规则，不额外开放陌生人搜索或群发。
- 限制的是别人向自己新发送邀请，不限制自己主动向别人发送；向别人发送时按对方设置判断。
- 所有发送入口，包括选人、再约一场和互邀发送，都由服务端按接收方最新设置及当前好友关系校验，不能只在页面隐藏按钮。
- 被拦截时提示发送方“对方仅允许好友约球”，不创建邀请、不发通知、不占用自己发出邀请的状态；用户可选择其他人，不自动添加好友。
- 开关只影响之后的新发送，不自动取消此前收到的邀请、已接受的约球、等待或进行中的比赛；原有邀请仍可接受/拒绝。已被拒绝的发送在关闭开关后也不会自动补发。
- 开启后新成为好友则可以发送；解除好友后再发送则按非好友处理。判断以发送时服务端检查结果为准，不信任选人页的旧状态。

## 6. 过期、其他比赛与异常

### 只有约球失效时间

- 今天16点—17点，今天18点仍可进入；明天06:59:59可进入，明天07:00不可再接受或进入。
- A在06:59进入等待，B在07:00才进入：约球已失效，不创建比赛，退出等待。
- 双方在07:00之前已正式开始：继续比赛，时间区间不控制比赛结束。
- 到期后移出活动卡、不阻止新约球、历史显示已失效。重新约需要新记录和对方接受。
- 旧的发送后24小时规则需替换，不能与本规则同时生效。
- 后台清理可延后，但页面展示、是否可以重新发起、过期操作拒绝必须到点生效，不能等待定时任务。

### 与其他比赛的关系

等待不是正式比赛，不能阻止本人去和其他人打球。开始另一场正式比赛时，退出旧约球的等待，原约球未过期则保留。

双方准备正式开局时重新检查比赛冲突：本人已有比赛，提供继续当前比赛；对方已有比赛，提示稍后再试。不能覆盖已有比赛，也不能把查询失败当成没有比赛。

### 必要的一致性规则

- 双方同时点击、连点、超时重试、多设备操作只创建一场比赛；同时接受多条邀请也不能形成两场未结束约球。
- 同人互邀合并、接受新邀请并关闭旧邀请、旧邀请被对方接受等竞争操作，由服务端确定唯一结果。失败不丢失原邀请，重试不重复匹配或覆盖已确定的比赛类型。
- 取消/拒绝先成功，不能再开局；正式开局先成功，则显示真实比赛，不能谎报“已取消且没有比赛”。
- 退出等待先成功，另一人进入后只能自己等待；正式开局先成功，不能再用退出等待抹掉比赛。
- 接受、进入、退出结果不确定时先核实，不在离线时提前声称退出成功。
- 通知或实时消息漏达，重新进页面、回前台、重连后仍能恢复最新状态；加载失败不能显示成没有约球。
- 只允许本人处理自己的进入/退出，不能冒充对方；切号后旧数据不能回写新账号。
- 保留现有登录、安全校验与有界纯读规则，不因免扫码而取消普通扫码路径的凭证检查。

## 7. 正式比赛与再约

双方主动进入并成功创建比赛后，才启用计时、记分和结算。此后返回或断网不抹除比赛，不能再用“放弃约球”绕过正式比赛的结束规则。

- 正常结束：关联对局完成后，同步将约球标为已完成，保留赛果入口，双方立即可以发起或接受下一次约球，无需额外点结束约球。
- 关联对局按现有规则取消或作废：约球同步标为已结束，并注明对局取消/作废，不伪装成正常完成，不自动恢复为已接受。
- 结束操作改为“向右滑动结束对局”：双方任意一位参与者从左端滑块滑到终点并松手即可结束，不等待对方同意、不再弹二次确认。适用于本需求中的排位与练习对局。
- 单击轨道、未滑到终点松手、触摸被取消均不结束，滑块回到起点；支持触摸、鼠标与键盘操作。
- 结束成功后双方显示赛果，约球同步完成；另一方不在线也不阻塞，回来后看到已结束。提交失败保留进行中状态并允许重试，不提前显示成功。
- 这一步由后端随对局终态处理完成，不依赖某个人打开赛果页或手动刷新；“对局”“我的”和记录页读取一致，旧通知不能重新开局。
- 重复结束请求不会重复结算或把已结束约球恢复。只更新当前比赛实际关联的约球，不误结束后来新发起的约球；无关联约球的普通比赛不受影响。
- 约球取消、拒绝、失效：只有约球记录，不生成“已取消比赛”充数。
- 再约入口统一叫“再约一场”：带入对手和球种，使用新的合法时间，重新发送与接受。
- 一条约球最多关联一场正式比赛；“再来一局”走新比赛流程。

### 历史对局详情里的“再约一场”

路径：`对局记录 → 某场对局详情 → 再约一场 → 发起约球页`。详情放入口即可，不给每条列表记录堆操作按钮，也不把约球列表搬进对局记录。

- 自己参与、且有明确平台对手的历史比赛均可再约，不要求原比赛由约球创建。旁观或仅担任裁判的记录不显示该按钮；不可邀请的账号沿用现有校验。
- 自动带入对手、球种，并把上一场比赛类型作为可修改的预填；发送前清楚展示。时间使用新的合法默认区间，不复制旧日期，不点击即发送。
- 有未结束约球时引导处理当前约球；自己发出的邀请仍待回应时，先取消原邀请才能重新发起。收到未回应邀请不妨碍再约。
- 约球记录、报表、交锋记录和赛后涉及同一功能的入口文案均使用“再约一场”，复用同一发起流程。
- 约球记录负责邀请和终态，对局记录只展示真实发生的比赛；没打成的约球不能进入对局记录。

## 9. 验收

使用双账号，再加第三账号验证等待不阻止其他正式比赛。

| 场景 | 必须结果 |
| --- | --- |
| 发起、接受 | 两页信息一致，接受不创建比赛；约球时所选比赛类型在接受卡可见，开局直接沿用 |
| 收到邀请未回应，再约别人 | 可以发起，无需先拒绝，原收到邀请保留 |
| 自己发出的邀请未回应，再约别人 | 阻止新发送，先取消旧邀请；并发发送同样受限 |
| 收到多条邀请，同时自己发出一条 | 仅收到不改变已发出的邀请；接受时才按明确分支处理 |
| A与B同类型互邀，A接受B的邀请 | 匹配为一次已接受约球，两页及原通知指向同一条，不创建比赛 |
| 同人同类型，但预计时间不同 | 可以匹配，按本次接受邀请的时间展示并计算失效时间，不增加时间选择 |
| 同人但球种或比赛类型不同 | 不直接匹配，不自动修改/取消邀请，清楚提示类型不同 |
| 双方同时接受互邀 | 只匹配一次，不覆盖首次成功确定的类型和时间 |
| A发给B未回应，A接受C | 明确提醒；取消弹框则不变，确认后接受C与关闭旧邀请一起成功，B收到取消反馈 |
| 提醒弹框打开后B先接受旧邀请 | A不能再接受C，显示与B已有约球，不关闭已成功的旧约球 |
| 接受C失败或C的邀请已失效 | 不关闭自己发给B的邀请，不谎报已约好 |
| 已接受/等待/本次正式比赛未结束，再接受其他人 | 拒绝新接受并可查看当前约球，不自动拒绝其他收到邀请 |
| 自己旧邀请被拒绝/取消/过期 | 可接受新邀请，不把拒绝算作已有约球 |
| 默认设置下好友与非好友最近对手 | 都能发送，无隐藏的必须好友限制 |
| 开启仅允许好友约球 | 好友可发送，非好友（含最近对手）发送被拒绝，无邀请、无通知，不阻止发送方向其他人发起 |
| 从再约一场/互邀入口或绕过前端发送 | 同样按接收方最新设置及好友关系判断，不能绕过限制 |
| 自己开启开关后主动向别人发送 | 不因自己的开关被阻止，按接收方设置判断 |
| 切换设置、换设备、好友关系变化 | 设置按账号持久化；发送检查最新结果，不能使用旧页面状态放行 |
| 设置读取/保存失败 | 不假装关闭或保存成功，原状态可恢复并可重试 |
| 开启前已有邀请或已接受约球 | 不自动取消，原流程仍可继续；关闭开关不自动补发曾失败的邀请 |
| 时间选择 | 仅三天与整点；不重复选人和球种 |
| 提前进入 | 尚无人进入时先进入的人提示一次；另一人看到对方已在等待则直接进入，无第二次提示；A/B互换同样成立 |
| 对方退出等待后提前进入 | 重新按无人等待判断，显示提前提示；取消提示不取消约球，正常及晚到仍直接进入 |
| A先进入、B未进入 | A看见B待进入，无比赛ID、计时、比分、积分、正式比赛占用 |
| B只看通知或上线 | 不算进入，不自动开局 |
| B进入 | 双方同一场比赛；同时点、重试、多设备都不重复创建 |
| B放弃 | 约球结束，A在等待页自动退出；离线恢复正确；无比赛数据 |
| 普通返回与锁屏 | 继续等待，主页面有本人等待卡；恢复页面不重复提交进入 |
| 退出等待 | 保留约球，对方不再显示本人已进入；可稍后重新进入 |
| A等待、B去与C比赛 | 不因A等待而受阻；旧约球不能并发创建冲突比赛 |
| 取消/退出与进入并发 | 只有一个真实结果，不误报无比赛或删掉已开始比赛 |
| 跨午夜且页面未关闭 | 今天变昨天，明天早晨7点变今天早晨7点；实际日期不变，前后台恢复一致 |
| 次晨07:00 | 即使清理任务停机也失效，自己过期邀请不再阻止重新发起；旧页面/通知不能开局；界面只显示“已失效” |
| 查看更早/跨年的记录 | 用月日或带年份的日期，不沿用错误的今天/昨天文案 |
| 截止前已正式开始 | 07:00后比赛正常继续 |
| 断网、切号、通知漏达 | 能恢复事实，无串号、无错误成功提示 |
| 约球结束后无通知可用 | 对局页约球记录可查原因和重新约球 |
| 单方滑动结束 | A或B独自滑到终点并松手即结束，不要求对方操作，对局和约球一起完成 |
| 点击轨道、滑动未完成、触摸取消 | 不结束，滑块复位；键盘可完成同一操作 |
| 结束失败、重复结束或另一方离线 | 失败不报成功；重复操作不重复结算；成功不依赖另一方在线，恢复时显示最新赛果 |
| 正式记分、积分与争议 | 保持相应既有规则，不用旧双确认流程阻塞新结束操作 |
| 比赛完成后再约 | 约球同步完成，双方立即可再约，赛果可查，无需手动结束旧约球 |
| 对局详情点击再约一场 | 正确预填对手、球种和可修改的比赛类型，使用新时间；不自动发送，遵守已有约球限制 |
| 扫码创建的历史比赛、旁观/裁判记录 | 自己参与且有平台对手的历史比赛可再约；仅旁观/裁判不显示按钮，未打成邀约不进入对局记录 |
| 比赛取消/作废、重复结束、双方离线 | 约球同步结束且原因正确；重复请求无额外结算，回到两页无旧约球阻塞 |
| 新约球已发起后收到旧比赛结束重试 | 仅处理旧比赛关联记录，不影响新约球 |

走查四条链路：正常开局；B放弃、A退出；误点后退出等待再进入；返回/锁屏后恢复等待或继续已开始比赛。

**完成标准：用户找得到约球、知道谁在等谁、能进入也能退出；没打成不留虚假比赛，正常开局不重复操作。**
