# 熟人约球｜双人流程与低保真原型

> 版本：W1.3，结束对局改为单方滑动，配套 [PRD V1.3](./familiar-player-quick-start.md)。
> 文字线框用于评审页面与交互，不是可运行页面；不修改应用代码。
> 配套：[可点击高保真 HTML 预览](../previews/quick-match-ui/index.html) · [打开与演示说明](../previews/quick-match-ui/README.md)。
> 沿用现有组件与 `DESIGN.md`。下图以发起人选择“排位”为例，不代表固定默认排位；其他比赛类型同样在发起时选择、开局直接沿用。

## 1. 主流程与入口

```text
发起约球 → 接受 → A进入等待 → B进入 → 正式比赛
                         ├─ B放弃 → A退出等待，本次无比赛
                         └─ A退出等待 → 保留约球，稍后再进
```

“对局”和“我的”展示同一条约球，不是两套流程：
- 对局页首屏展示现有约球；无约球时保留原扫码等即时开局优先级。
- 我的页只替换原 status-card 的空态，不重排其他内容。
- 对局页始终保留“约球记录”，卡片消失后仍可查原因和再约。
- 对局记录中的比赛详情提供“再约一场”，带入对手与比赛信息，不要求原比赛来自约球。
- 通知定位具体约球，打开只查看，不替用户点进入。
- 当前正式比赛优先；收到未回应邀请不能盖住已接受/等待中的约球或自己发出的邀请。
- 收到邀请可以暂不处理；只有收到未回应邀请时，仍可发起自己的约球。

```text
┌─────────────────────────────┐
│ 对局                        │
│                             │
│ [扫一扫]      [出示二维码]  │
│ （沿用原即时开局主次关系）   │
│                             │
│ [发起约球]        约球记录  │
│ 收到的邀请               › │
│                             │
│ 其他原有内容                │
└─────────────────────────────┘
```

有约球时优先展示下述卡片，即时开局入口仍可找到。正常已登录冷启动落在其他Tab，点“对局”再点“进入”即可，无需翻记录。

## 2. P01—P02｜选人、发起

```text
┌─────────────────────────────┐
│ 〈返回             选择球友  │
│                             │
│ 好友                        │
│ [头像] 小王   身份辅助信息 ›│
│ [头像] 小陈   身份辅助信息 ›│
│                             │
│ 最近对手                    │
│ [头像] 小张   身份辅助信息 ›│
└─────────────────────────────┘
```

默认好友和最近对手都能约；对方开启“仅允许好友约球”后，非好友最近对手也不能新发送邀请。点人直接进入表单，不另设“确认选人”。“再约一场”带入对手与球种，跳过选人页。没有可选球友时可去现有添加好友入口；加载失败显示重试，不当作没有好友。

```text
┌─────────────────────────────┐
│ 〈返回             发起约球  │
│                             │
│ [头像] 小王          更换   │
│                             │
│ 打什么                      │
│ [中式八球●] [斯诺克] […]   │
│                             │
│ 预计什么时候                │
│ [今天●] [明天] [后天]      │
│     [16点 ▾] 到 [17点 ▾]   │
│ 预计时间仅作提醒             │
│                             │
│ 比赛类型                    │
│ [排位●]         [练习]     │
│ 按所选类型显示赛制等信息     │
│ 附言（选填）                │
│ [                         ]│
│                             │
│ 明天早晨7点失效             │
│ [        发送约球         ] │
└─────────────────────────────┘
```

- 日期原位单选，小时用简单单列选择，不出现年月日、分钟秒。
- 结束必须晚于开始，错误原位提示。按北京时间默认下一个可用整点的一小时区间；当天无可用区间则展示明天。23点—24点在次晨07:00失效，不多延一天。
- 比赛类型在此选择，接收方看得到，开局直接使用，不重新选择。必要赛制和积分说明沿用所选类型的现有规则。
- 发送成功回对局页显示已发送卡，轻提示“约球已发送”，不再问要不要看记录。
- 自己发出的有效邀请尚未收到回应时，提示先处理原邀请，提供查看和取消；先取消才能换人发送。已有未结束约球（含已接受、等待中及本次正式比赛）时，不能额外发起或接受其他约球。
- 只有收到未回应邀请时可以发送，不强迫拒绝，不自动清除收到的邀请。并发发送由服务端保证不重复。
- 发送中防连点；失败保留表单，结果不确定先查，不引导重复发送。

## 3. P03—P04｜等待回应 / 收到约球

```text
A：发出                         B：收到
┌──────────────────────────┐  ┌──────────────────────────┐
│ 与小王的约球    等待回应  │  │ 小李约你打一场  待你回应  │
│ 中式八球                 │  │ 中式八球                 │
│ 今天16点—17点           │  │ 今天16点—17点           │
│ 排位                     │  │ 排位                     │
│ 明天早晨7点失效          │  │ 明天早晨7点失效          │
│                          │  │                          │
│ 取消约球                 │  │ [这次不了] [接受约球]   │
└──────────────────────────┘  └──────────────────────────┘
```

B接受后双方原位显示P05，不自动进入等待，不创建比赛。B拒绝或A取消则结束约球，告知另一方，不要求填写理由。

B也可以什么都不点，继续发起自己的约球。收到多条邀请通过“收到的邀请”在现有列表查看，不将每条卡片都堆在首页：

```text
┌─────────────────────────────┐
│ 〈返回           收到的邀请  │
│ 小李 · 中式八球 · 排位     │
│ 今天16点—17点              │
│ [这次不了]      [接受约球] │
│ ─────────────────────────  │
│ 小陈 · 斯诺克 · 练习       │
│ 明天18点—19点              │
│ [这次不了]      [接受约球] │
└─────────────────────────────┘
```

此列表复用约球记录的收到分组，不新增排期系统。收到邀请不用马上处理；点击接受才执行以下分支。

### 同一人、同一类型互邀：直接匹配

A给B发了邀请，B也给A发了同类型邀请。A点接受B的邀请后，两边都显示P05，轻提示“已约好，与对方的邀请已合并”。不再取消一次、接受一次，也不直接进入比赛。

两条原邀请和通知都指向同一次约球，不残留重复待回应卡。重复点击或双方同时接受不会出现第二条已接受约球。

时间不同没关系：沿用本次点击接受的邀请时间，两人的P05显示同一时间，不再弹时间选择。参与匹配的邀请仍须有效。

球种或比赛类型不同则不直接匹配，提示“你们发起的约球类型不同，不能直接匹配”，提供“查看已发出的邀请”。不自动改类型、不自动关闭原邀请；如需改约，用户先取消自己未回应的邀请，再接受收到的邀请。

### 换人接受：提醒后关闭自己未被回应的邀请

示例：A发给小王的邀请还没回应，此时A点接受小陈的邀请。

```text
┌─────────────────────────────┐
│ 接受小陈的约球？            │
│                             │
│ 接受后会自动关闭已发出的邀请 │
│ 原邀请：你发给小王的约球    │
│                             │
│ [暂不接受]      [确认接受] │
└─────────────────────────────┘
```

- 暂不接受：两条邀请都不变。
- 确认成功：A与小陈显示P05，小王看到原邀请已取消；其他未回应的收到邀请保留。
- 不先跳去取消页，也不再问第二次取消确认。
- 新邀请接受失败，不关闭原邀请；若弹框期间小王已先接受，则显示已有约球，不能覆盖。

### 已经约好且未结束：不能再接受

收到邀请仍可查看或拒绝；接受位置显示“已有约球”，点击提示：

```text
┌─────────────────────────────┐
│ 已有未结束的约球            │
│ 请先处理与小王的当前约球。  │
│                             │
│ [知道了]      [查看当前约球]│
└─────────────────────────────┘
```

不提供“一键换人”覆盖已经接受的约球。退出等待不解除限制，本次比赛开始后也仍受限制，直到本次结束。点开同一次已接受或已合并记录则查看现有约球，不当作接受新邀请。

## 4. P05｜已接受

```text
┌─────────────────────────────┐
│ 与小王的约球          已接受 │
│ 中式八球                    │
│ 今天16点—17点              │
│ 排位                        │
│                             │
│ 双方进入后正式开始          │
│ 明天早晨7点失效             │
│ [        进入对局         ] │
│          取消约球           │
└─────────────────────────────┘
```

任意一人可以先进入，不固定邀约发起人。正常或晚于预计区间、但未过期时，一次点击直接进入。

仅在还没到预计时间、且对方尚未进入时提示先进入的人：

```text
┌─────────────────────────────┐
│ 现在进入吗？                │
│ 预计今天16点开始。          │
│ 双方进入后才会正式开局。    │
│ [稍后再打]      [现在进入] │
└─────────────────────────────┘
```

关闭提示不取消约球，不替对方进入。对方已经在等待时，后来的人直接进入，即使未到预计时间也不再提示；若对方已退出等待，则重新按无人等待判断。返回已有等待页只是恢复页面，不重复提示。

## 5. P06｜A已进入，等待B

```text
┌─────────────────────────────┐
│ 〈返回             等待对手  │
│                             │
│ 中式八球                    │
│ 排位                        │
│                             │
│ [小李头像]      [小王头像]  │
│    已进入          待进入   │
│                             │
│         等待小王进入        │
│      双方进入后正式开始     │
│                             │
│ 返回或锁屏后仍会等待        │
│ 暂时不打，可以退出等待      │
│                             │
│ [退出等待，保留约球]        │
│          取消本次约球       │
└─────────────────────────────┘
```

这是等待人，不是加载页面：不转无限加载圈，不展示0:0、比赛计时、记分按钮，也不提前创建比赛。

| 动作/事件 | 结果 |
| --- | --- |
| 普通返回、手势返回 | 只导航，仍在等待，主页面显示P06a |
| 锁屏、切后台 | 继续等待，回来读取最新结果 |
| 退出等待，保留约球 | 本人变回待进入，成功后提示并返回，不另弹确认 |
| 取消本次约球 | 一次确认后结束约球 |
| B进入 | A在等待页自然转入正式比赛；A在其他页只提醒，不抢页面 |
| B放弃 | A在等待页提示并自动退出；离线恢复后显示终态 |
| 约球次晨07:00失效 | 结束等待，恢复普通入口，记录可查 |

等待不增加独立倒计时。本人退出、取消、对方放弃、约球过期或转去开始其他正式比赛时停止等待；正常返回不暗中退出。

## 6. P07｜B选择进入或放弃

```text
┌─────────────────────────────┐
│ 小李已进入，等你一起开始    │
│                             │
│ [小李头像]      [我的头像]  │
│    已进入          待进入   │
│                             │
│ 中式八球 · 今天16点—17点   │
│ 排位                        │
│                             │
│ [        进入对局         ] │
│          放弃本次约球       │
└─────────────────────────────┘
```

- 点进入：检查A仍在等待、约球有效且双方无比赛冲突，成功后创建同一场正式比赛，不扫码、不重选类型。
- 若A刚退出等待，B成为等待方，显示等待小李，不假称比赛已开始。
- B可以直接在卡片放弃，不必先进入页面才能拒绝。

放弃确认：

```text
┌─────────────────────────────┐
│ 放弃本次约球？              │
│ 对方将退出等待，约球结束。  │
│ 不会产生比赛和战绩。        │
│ [继续约球]      [确认放弃] │
└─────────────────────────────┘
```

成功后B返回来源页；A等待页提示“对方已放弃，本次约球已结束”并自动退出，不要求A再点确认。若并发操作已经正式开局，必须显示真实比赛结果，不能继续声称未产生比赛。

## 7. P08—P09｜正式比赛与记录

P08保留比赛页面：只有双方进入并成功创建后，才出现正式比分、计时、记分。两人共用同一个比赛ID，不用放弃约球抹除比赛。

结束按钮替换为滑块：

```text
┌─────────────────────────────┐
│ [ → ]   向右滑动结束对局 ›› │
└─────────────────────────────┘
滑到终点后松手即可结束，无需对方确认。
```

- 任意一方完成滑动即可结束本场，不再出现申请结束、等待对方批准或撤回结束请求。
- 从左端滑块开始拖动，点击右侧轨道不能直接结束；未到终点或触摸中断则复位。
- 支持鼠标、触摸和键盘，滑动本身承担防误触，不追加确认弹框。
- 成功后双方对局页更新为赛果，约球同步结束；对方不在线不影响结束，回来后读取最新结果。
- 失败时保留进行中状态可重试，重复操作不重复结束。这是新设计，App与后端的旧结束确认流程尚未修改。

约球结束后移出活动卡，但始终可从 `对局 → 约球记录` 查看，不依赖通知。

```text
┌─────────────────────────────┐
│ 〈返回             约球记录  │
│                             │
│ 与小王的约球          已失效 │
│ 中式八球                    │
│ 昨天16点—17点              │
│                             │
│ [        再约一场         ] │
└─────────────────────────────┘
```

取消/拒绝记录显示对应原因。关联比赛正式结束后，约球同步结束，不要求用户再处理一次：

| 对局结果 | 约球记录 | 对局/我的主卡 |
| --- | --- | --- |
| 正常完成 | 已完成，可查看赛果 | 移除旧的等待/进行中入口，恢复可发起/接受下一次约球 |
| 按正式比赛规则取消或作废 | 已结束，显示取消/作废原因 | 不再被旧约球阻挡，不自动恢复已接受 |
| 滑动未完成或提交失败 | 仍未结束 | 滑块复位，保留当前比赛，不假报完成 |

后台即完成对应状态更新，双方离线、没打开赛果页也不影响；重回页面显示最新结果。只处理本场关联的约球，旧比赛的重试通知不能覆盖新约球。

“再约一场”带对手和球种，使用新的合法时间，确认后发送，不自动恢复旧记录；已有未结束约球时先引导处理，不能直接再发。

### 跨午夜与失效文案

以今天16—17点、次晨7点失效的未开局约球为例：

| 查看时机 | 预计时间显示 | 失效提示/状态 |
| --- | --- | --- |
| 当晚 | 今天16点—17点 | 明天早晨7点失效 |
| 过了00:00，尚未到07:00 | 昨天16点—17点 | 今天早晨7点失效 |
| 到07:00 | 昨天16点—17点 | 已失效 |

失效后只保留“已失效”状态，不重复一句具体失效时刻。两页卡片、邀请列表与详情都按北京时间更新；页面跨午夜、锁屏或后台回来均更新，不修改实际约球日期。较早记录显示月日，跨年带年份。

### P10｜历史对局详情里的再约入口

```text
┌─────────────────────────────┐
│ 〈返回             对局详情  │
│                             │
│ 小李             小王      │
│          5 : 3              │
│ 中式八球 · 排位 · 已结束   │
│                             │
│ 原有赛果、局数与战绩内容    │
│                             │
│ [        再约一场         ] │
└─────────────────────────────┘
```

- 从对局记录点进详情，再点按钮进入P02；不在每条列表上堆按钮，不另开约球列表。
- 自己参与且有明确平台对手的历史比赛才显示；扫码开始的比赛也支持。仅旁观/裁判记录不显示，账号状态仍按现有规则校验。
- 自动带入对手、球种、上一场的比赛类型；类型发送前可改。时间使用新的合法默认值，不复制上一场日期，也不直接发送。
- 已有未结束约球提示先处理；自己发出的邀请未回应，先取消才能再发；仅收到未回应邀请不限制。
- 约球记录、报表、交锋与赛后同类入口统一叫“再约一场”。对局记录只保留真实比赛，不混入取消或未打成的邀约。

### P11｜设置：仅允许好友约球

路径：`我的 → 设置`。在现有“隐藏战绩”附近加一行开关，其他设置保持原样，不新增设置子页。

```text
┌─────────────────────────────┐
│ 〈返回                 设置  │
│                             │
│ 主题模式                    │
│ 通知管理                 › │
│ 隐藏战绩             [开关]│
│ ─────────────────────────  │
│ 仅允许好友约球       [关闭]│
│ 开启后，非好友无法向你      │
│ 发送约球邀请                │
│ ─────────────────────────  │
│ 隐私政策                 › │
│ 其他原有设置                │
└─────────────────────────────┘
```

- 默认关闭，点开关直接保存，不增加确认弹框。保存中防重复操作，失败恢复原值并提示重试；读取失败不画成默认关闭。
- 设置跟随账号，不仅保存在当前设备。
- 开启后仍能收到好友邀请；不自动取消原收到邀请或已接受约球。
- 自己仍可主动约别人，能否发送按对方设置判断。
- 非好友发送被拦截时提示“对方仅允许好友约球”，保留发起页与更换球友入口；不自动加好友、不创建邀请、不发送通知。
- 选人、再约一场、互邀发送都适用，由服务端校验；不以灰掉按钮代替真实检查。

## 8. 异常反馈

| 情况 | 用户看到与可做的事 |
| --- | --- |
| 加载失败 | 保留上下文，“暂时无法确认约球状态，重新加载”；不是无约球 |
| 非好友向开启限制的用户发送 | 提示“对方仅允许好友约球”，不创建邀请或通知，可换人发起 |
| 设置保存失败 | 恢复原开关值，提示保存失败可重试，不假称限制已生效 |
| 提交中或超时 | 防连点，先查结果，不重复发送/创建，不提前声称退出成功 |
| 接受新邀请与对方接受原邀请同时发生 | 只能约好一场；显示先成功结果，不误关闭已接受约球 |
| 同人同类型互邀重复接受 | 恢复同一次约球，不重复匹配、不覆盖已确定内容 |
| 同人但类型不同 | 不直接匹配，提示查看原邀请，不自动改类型或关闭 |
| 比赛已结束，返回主页面 | 约球同步已结束，可以继续下一次约球，不要求再点取消 |
| 自己已有正式比赛 | 提示并提供继续当前对局 |
| 对方已有正式比赛 | 提示稍后再试，约球仍保留；不能覆盖比赛 |
| A等待、B想与别人打 | 等待不占比赛资格，其他正式开局成功后清除旧等待 |
| 取消/退出和进入同时发生 | 服务端先成功的结果为准；已开局不能报无比赛取消 |
| 次晨07:00已到 | 约球失效、不可接受/进入，自己过期的邀请不再阻止新发起；已正式开始的比赛不受影响 |
| 推送漏达、重连、换设备 | 读取最新状态恢复，不用旧卡片开局 |
| A离线时B放弃 | 服务端立即结束，A回来后退出旧等待，不承诺断网设备瞬间跳页 |

## 9. 双人走查

| 路径 | A | B | 结果 |
| --- | --- | --- | --- |
| 正常 | 发起、等待回应、进入等待 | 接受，再点进入 | 正式创建一场比赛 |
| 放弃 | 正在等待 | 放弃并确认 | A自动退出，无比赛数据 |
| 误点 | 进入后点退出等待 | 恢复看到已接受 | 约球保留，之后任意人可重新进入 |
| 返回/锁屏 | 仍在等待，回来可恢复 | 点进入 | 正式开始，A回来继续同场，不重复开局 |
| 到期 | 06:59进入等待 | 07:00才进入 | 失效、退出等待，无比赛 |

走查重点：
- 双入口都找得到同一条约球，取消后找得到记录。
- B接受不等于进入；A等待不等于正式比赛。
- 正常时段双方各点一次，无重复选型、扫码或批准步骤；提前时仅先进入的人看到提示，对方已在等待时直接进入，角色互换也一致。
- 返回、退出等待、取消整个约球含义清楚。
- 拒绝、取消和失效不产生一场“已取消比赛”充数。
- 弱网、同时点击、返回恢复不会重复创建或显示虚假成功。
- B收到A邀请不回应，仍可向C发起；原收到邀请保留。B自己发给C的邀请未回应时，必须先取消才能换人再发。
- 默认好友与最近对手都能约；接收方开启仅允许好友后，非好友所有发送入口都被拦截。发起时选择的比赛类型在双方卡片和正式比赛中一致。
- 开关默认关闭、跨设备保持；保存失败恢复原值，已有邀请/约球不自动取消，自己的开关不限制自己向别人发送。
- A、B同类型互邀后接受，直接合成一次约球；时间不同也可以，同时接受只保留一次结果。
- 同人不同类型不直接匹配，不偷偷选其中一种类型或关闭旧邀请。
- A发给B未回应，接受C时出现一次关闭旧邀请提醒；取消不变，确认成功才一起关闭旧邀请。
- 弹框期间旧邀请被接受或新邀请失效，不能先关闭旧邀请再报错。
- 已接受、等待中或本次比赛未结束时，不可再接受其他人；收到的邀请仍可暂不回应。
- 任意一方滑动结束后，两边显示赛果，约球同步完成；另一方无需批准。滑动中途松手、误点、取消触摸不得结束。
- 跨午夜日期随当前北京时间变化，实际约球日期不变；失效后只显示“已失效”。
- 历史对局详情“再约一场”正确预填对手和类型，使用新时间，不自动发送；仅旁观/裁判无此按钮。

## 10. 定稿说明

本原型无待确认产品项：比赛类型由发起时选择；默认好友和最近对手都可约，接收方可开启仅允许好友；收发与互邀按正文处理；统一北京时间和次晨07:00失效；提前且无人等待时才提示先进入的人，对方已在等待则直接进入；比赛结束同步结束约球。

项目尚未上线，不设计历史邀约兼容页面或旧流程入口；测试、开发、本地的相关结构和数据可在实施时重构或清理。新流程正常产生的约球记录仍保留，不取消记录入口。

结束交互采用单方滑动，不沿用旧的对方确认步骤；记分、积分和争议处理不另造一套规则。HTML预览已演示此交互，App/后端未改，正式实施须同步调整结束入口与约球状态更新；本轮未执行数据清理。
