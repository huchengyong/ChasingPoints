# 后台接口访问控制：验收记录

对应变更：`openspec/changes/archive/2026-10-26-enforce-admin-api-access`。记录日期：2026-10-26。

## 1. 背景与发现

管理员令牌和用户令牌用同一个密钥签发，只靠用户 ID 的正负区分（管理员为负数）。全局中间件没有任何一层要求 `/api/admin/*` 必须是管理员，身份校验依赖各 logic 自己调用 `GetAdminIDFromCtx`。

逐个核对 `chasing_points.api` 中 39 个带 JWT 的后台接口（不含登录、初始化、存在性检查三个公开入口）：

| 状态 | 数量 | 接口 |
| --- | --- | --- |
| 校验管理员身份 | 19 | 赛事情报 9 个、管理员信息、修改密码、社区帖子审核、反馈处理、装备目录 6 个 |
| 没有校验 | 20 | 用户列表、更新用户状态；球馆列表、审核、奖励配置读写、奖励记录；会员权益配置读写；信誉配置读写、信誉日志；大模型配置读写；社区帖子列表；反馈列表；仪表盘 3 个；对局列表 |

其中会员权益、信誉、大模型三个“更新配置”接口调用了 `GetAdminIDFromCtx`，但写成 `adminID, _ := …` 忽略了错误，只用来记录操作人，并没有拒绝普通用户。

结论：任何登录的普通用户，用自己的令牌就能调用这 20 个接口。该问题在本变更之前就存在，本次排查中发现。是否有人利用过，见第 7 节的历史日志排查。

## 2. 修复

- 新增全局中间件 `AdminAccessMiddleware`：`/api/admin/` 下除 `login`、`init`、`exists` 外，要求令牌里的用户 ID 为负数。普通用户令牌返回 403，没有身份返回 401。
- 路径先做 `path.Clean`，与 go-zero 路由器一致，`/api//admin/…`、`/api/./admin/…`、`/api/x/../admin/…` 不能绕过。
- 注册顺序在 `ActiveUserSessionMiddleware` 之前，被拒绝的请求不再查用户表。
- 把全局中间件注册抽成 `registerGlobalMiddlewares`，`main` 与测试共用。不改 `.api`、不改表结构、不改管理后台前端。
