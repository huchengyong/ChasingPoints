# 客户端读性能真机验收清单

> 适用于 OpenSpec 变更 `optimize-client-api-read-performance`。建议分别在 Android/iOS App 和至少一个微信开发者工具或真机环境执行。任何截图、日志或录屏均不得包含 access token、手机号、短信验证码、数据库连接串或后台账号密码。

## 1. 验收准备

- [ ] 后端已部署本次兼容版本，`CompetitiveReadModel.ReadMode` 当前值已记录。
- [ ] 准备两个可安全切换的普通测试账号 A/B，至少一个账号有历史比赛、好友、通知和赛季数据。
- [ ] 开启客户端请求调试计数：`globalThis.__CHASING_POINTS_REQUEST_METRICS__ = true`。
- [ ] 清空请求计数但不要清理服务端 Redis：调用 `resetRequestMetrics()` 或重启测试 App。
- [ ] 记录测试时间、App 版本、平台、网络类型、后端版本和账号编号，不记录凭据。
- [ ] 确认服务端能按 `request_id` 查询 `http_request_completed` 与关联 SQL 指标。

## 2. 赛季页首屏与生命周期

### 2.1 首次进入存在活动赛季

- [ ] 冷启动并登录后首次进入“赛季”页。
- [ ] 页面立即显示加载态，不出现永久空白或永久“加载中”。
- [ ] 请求完成后显示赛季名称、日期、我的赛季数据和榜单；部分区块不可用时其他区块仍可显示。
- [ ] 首次 `onMounted` 与 `onShow` 合计只产生 **1 次** `GET /api/season/overview`。
- [ ] 首屏不得额外请求 `current-season`、`my-record` 或重复榜单第一页。

### 2.2 页面保留与失效

- [ ] 从赛季页进入报告或其他子页面，再返回；scope 未变化时不重复请求 overview。
- [ ] 收到 `user_data_updated` 的 `season` scope，或完成影响当前赛季的排位后返回赛季页，只刷新 **1 次** overview。
- [ ] 切换球种时只请求新球种的一次 overview。
- [ ] 点击“加载更多”只请求排行榜后续页，不重复请求赛季和本人记录。

### 2.3 无活动赛季/不可用

- [ ] 在无活动赛季或生命周期 unavailable 的测试环境打开页面。
- [ ] 页面结束 loading 并显示明确空状态文案。
- [ ] 不继续请求本人记录和赛季榜单。

## 3. 冷启动、前台恢复与 Tab 复用

- [ ] 登录后的 App 冷启动只执行 **1 次** `GET /api/user/bootstrap`。
- [ ] Bootstrap 完成后依次进入首页、观赛和“我的”，当前对局、通知角标和好友申请角标不被重复读取。
- [ ] App 切到后台至少 30 秒后恢复，单个前台代次最多执行 **1 次** Bootstrap。
- [ ] 首页首屏业务请求不超过 4；观赛页首屏不超过 1；“我的”首屏不超过 2。
- [ ] 排行榜首次进入同一球种只产生 1 次榜单请求。
- [ ] stats 详情首屏只产生 1 次 stats overview。
- [ ] H2H 首屏只产生 1 次 H2H overview，不出现 page size 10/100 双下载。

## 4. 认证隔离与旧响应保护

### 4.1 账号 A → logout → 账号 B

- [ ] 使用账号 A 打开“我的”、通知、好友申请、历史、H2H、对手、stats、荣誉和赛季页面。
- [ ] 在慢网或请求进行中退出账号 A，再登录账号 B。
- [ ] 账号 B 不显示账号 A 的资料、角标、列表、统计、H2H、荣誉或赛季本人记录。
- [ ] 账号 A 的延迟响应返回后不得覆盖账号 B 当前页面。
- [ ] Bootstrap reservation 不挂起；账号 B 能正常完成新 Bootstrap。

### 4.2 同账号认证代次变化

- [ ] 触发 token 刷新或重新登录同一账号，使 `authGeneration` 变化。
- [ ] 旧代次通知/好友申请计数和页面请求不得回写新代次。
- [ ] WebSocket 推送计数只更新当前 `ownerUserId + authGeneration`。

## 5. WebSocket 精确失效

- [ ] 完成一场有效排位，即使关闭“比赛结果通知”，双方仍收到 `user_data_updated`。
- [ ] 事件 scopes 至少能按业务影响失效 rank、stats、H2H、opponents、history、honor、season 和 leaderboard。
- [ ] 收到未读通知数/好友申请数事件时角标直接更新，不额外同时调用两个 count 接口。
- [ ] 断网期间完成比赛，恢复网络并前台 Bootstrap 后，竞技 revision 差异能使对应页面收敛到新数据。

## 6. 对局详情与分享当前竞技资料

- [ ] 在读模型 `disabled` 状态打开已完成比赛详情和分享页，当前胜率/最高分来自兼容旧事实，不显示由空快照产生的错误零值。
- [ ] 在 rebuild/audit 完成且读模型 `enabled` 的灰度环境打开同一比赛，数据与旧口径一致。
- [ ] 再完成一场新比赛后重新打开旧比赛：核心比分、局和过程不变，当前胜率和最高分反映最新数据。
- [ ] 分享页与结果详情的当前竞技资料一致。

## 7. 公开接口可选身份

- [ ] 未登录访问公开排行榜、榜单摘要和公开对局，公共列表正常显示且没有“我的排名”。
- [ ] 登录后访问排行榜和摘要，“我的排名”对应当前账号。
- [ ] 登录后使用好友观赛筛选，只显示当前 viewer 好友相关对局。
- [ ] 使用过期或无效 token 请求公开接口时返回 401，不得降级成匿名并继续展示个性化数据。

## 8. 缓存、弱网和手动刷新

- [ ] 首页与赛讯页在客户端 TTL 内复用同一赛讯，不额外发网络请求。
- [ ] 排行榜、静态规则/术语/地区/段位配置、会员套餐在有效 TTL/version 内复用。
- [ ] TTL 到期但已有旧值时先显示旧内容，再后台刷新；刷新失败不清空成功加载过的页面。
- [ ] 用户手动下拉刷新会绕过普通 TTL，且只发一次强制请求。
- [ ] 服务端 Redis 暂时不可用时可缓存读取仍能回源成功；不得出现登录串号或业务写失败。
