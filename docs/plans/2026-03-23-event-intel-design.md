# 赛事情报改造设计

## 背景

当前项目中的“赛事焦点 / 赛事大厅”建立在平台内赛事报名模型之上，用户在前台的主要动作是查看赛事、报名、退赛、查看对阵与赛后名次。现状存在两个明显问题：

- 用户价值偏弱。报名后缺少持续互动，用户感知更像“占坑”而不是“有内容可看”。
- 业务模型错位。现有 `tournament` 结构围绕 `报名人数 / 参赛者 / 创建者 / 对阵` 设计，不适合承载国际赛事赛程、赛况、赛果这类资讯型内容。

结合产品目标与现有代码结构，本次改造目标不是继续强化报名型赛事，而是将前台入口升级为“赛事情报”，首期覆盖：

- 斯诺克
- 中式八球
- 中式九球

其中斯诺克可逐步接入官方赛历，中式八球与中式九球首期优先通过 admin 手动录入维护。

## 目标

- 将首页“赛事焦点”升级为真正可消费的赛事内容入口。
- 将“赛事大厅”重构为“赛事情报”列表，支持按球种和状态查看最近值得关注的赛事。
- 让详情页从“报名详情”转为“赛事详情”，重点展示赛程、赛况、赛果、来源和跳转链接。
- 保留现有 `tournament` 模块作为平台内赛事能力，不与新资讯模型混用。

## 非目标

首期明确不做以下内容：

- 用户报名、退赛、签到
- 平台内赛事对阵生成
- 参赛者名单维护
- 实时比分抓取
- 复杂富文本 CMS
- 多来源自动去重与聚合

## 产品方案

### 首页

保留首页“赛事焦点”位置，但语义改为“焦点赛事”。

展示一条平台推荐或排序靠前的赛事资讯，字段以内容消费为主：

- 赛事名称
- 球种
- 状态：即将开始 / 进行中 / 已结束 / 已取消
- 时间提示
- 简短摘要

点击后进入赛事详情页。

### 列表页

将“赛事大厅”更名为“赛事情报”。

列表页提供两个维度的筛选：

- 球种：斯诺克 / 中式八球 / 中式九球
- 状态：全部 / 即将开始 / 进行中 / 已结束

列表卡片重点展示：

- 赛事标题
- 球种
- 地点或站点
- 时间
- 当前阶段
- 赛果摘要或最新进展
- 查看详情入口

不再展示报名进度、人数上限、报名按钮等平台内赛事字段。

### 详情页

赛事详情页展示信息以结构化内容为主：

- 基本信息：赛事名、球种、时间、地点、主办信息
- 当前状态：即将开始 / 进行中 / 已结束 / 已取消
- 阶段信息：例如资格赛、正赛、决赛日
- 最新赛果或进展摘要
- 来源说明
- 来源跳转链接

首期无需提供对局列表、签表、参赛者长列表或富文本正文。

### Admin 录入

新增 admin 端“赛事资讯”录入能力，用于维护中式八球与中式九球内容，并作为斯诺克半自动导入后的兜底校正入口。

录入项建议包括：

- 球种
- 赛事标题
- 来源名称
- 来源链接
- 封面图
- 摘要
- 国家 / 城市 / 场馆
- 开始时间 / 结束时间
- 当前状态
- 当前阶段
- 最新赛果摘要
- 是否推荐为焦点
- 排序时间
- 是否发布

## 数据模型

不复用现有 `tournaments` 表，新增独立“赛事资讯”模型。

建议新增主表 `event_news`，字段如下：

- `id`
- `title`
- `slug`
- `game_type`
- `source_type`
- `source_name`
- `source_url`
- `cover_image`
- `summary`
- `content`
- `country`
- `city`
- `venue`
- `start_time`
- `end_time`
- `status`
- `stage_text`
- `result_text`
- `featured`
- `sort_time`
- `published`
- `published_at`
- `created_at`
- `updated_at`
- `deleted_at` 或逻辑删除标记

首期不强制新增赛况时间线子表。后续若需要保留多次赛况更新，再补 `event_news_updates`。

## 接口设计

建议使用独立前缀，例如 `/api/event-news`。

前台接口：

- `GET /list`
- `GET /detail`
- `GET /featured` 可选

admin 接口：

- `GET /admin/list`
- `POST /admin/create`
- `POST /admin/update`
- `POST /admin/publish`
- `POST /admin/delete` 或软删除

## 与现有 tournament 模块的关系

- 现有 `tournament` 模块保留，不做破坏式迁移。
- 前台用户入口从 `tournament` 切换到 `event-news`。
- 旧的报名、退赛、签到、对阵逻辑暂不删除，避免影响潜在平台内赛事能力。
- 若后续确认平台内赛事彻底不再对用户开放，再决定是否下线旧页面。

## 数据来源策略

按球种拆分处理：

- 斯诺克：优先接结构更稳定的官方赛历与赛况入口，必要时人工校正。
- 中式八球：首期 admin 手动录入。
- 中式九球：首期 admin 手动录入，重点覆盖类似“独牙传奇中式九球”这类赛事。

不以“自动抓取全部赛事源”作为首期前提条件，先保证内容可持续更新。

## 改造范围

### 前端

- 首页焦点赛事数据源切换
- 列表页从报名卡片改为资讯卡片
- 详情页从操作型详情改为内容型详情
- 用户中心“赛事中心”入口继续保留，跳转至新列表页

### 后端

- 新增 `.api` 契约
- 新增 model / logic / handler
- 新增迁移表
- 新增 admin 录入与管理接口

### Admin

- 新增赛事资讯列表页
- 新增创建/编辑表单
- 支持发布、下线、推荐

## 风险与取舍

- 风险一：三个球种的数据源稳定性不同。应接受“首期以人工维护为主”的现实，而不是强行统一自动化。
- 风险二：旧 `tournament` 与新 `event-news` 并存会带来一定代码重复，但这是为了换取更低迁移风险。
- 风险三：首页焦点推荐若完全人工维护，运营成本会上升。可先通过 `featured + sort_time` 的组合降低维护复杂度。

## 推荐结论

采用“平衡方案”：

- 前台升级为“赛事情报”
- 后台新增独立资讯模型
- admin 端增加手动录入能力
- 旧 `tournament` 保留但不再作为前台主入口

这是当前最适合本项目的路线：既能快速给用户提供真实可看的赛事内容，又不会把未来平台内赛事能力彻底堵死。
