# 登录转化漏斗与品牌化入口重构设计

## 背景

当前 App 的欢迎页与登录页已经具备基础能力，但从转化与体验视角看，仍存在几处明显摩擦：

- 欢迎页同时给出“注册”和“登录”两个按钮，但最终都进入同一个手机号验证码页，路径承诺与实际行为不一致。
- 登录页主按钮文案是“登录 / 注册”，但页面顶部没有明确解释“未注册手机号将自动创建账号”，用户容易犹豫自己现在到底在做什么。
- 协议勾选位于页面底部，且在点击登录后才被强提示，用户常常是在完成填写后被打断。
- 第三方登录入口始终展示，但非 HarmonyOS 环境下只是 toast 拦截，形成“假可用”。
- 页面视觉已经开始往金色品牌靠拢，但欢迎页和登录页的结构重心仍偏“展示”，没有最大化服务于快速登录。

这些问题单独看都不大，但串成漏斗后，会共同拉低首登效率和第一印象。

## 目标

- 提升欢迎页到登录页的点击转化与登录完成率。
- 建立更清晰的一条主路径，让用户不再区分“登录”和“注册”。
- 让页面视觉更有竞技类产品的品牌感，同时不牺牲操作效率。
- 减少无效点击、误解和被动拦截，尤其是协议、第三方登录和错误反馈相关摩擦。

## 非目标

本次设计不包含以下范围：

- 登录方式扩展到微信、Apple 等新的第三方平台
- 后端认证逻辑改造
- 手机号绑定弹窗重做
- 管理后台登录页重构
- App 全站视觉语言重做

## 设计结论

本次采用“单一主路径 + 轻分流”的方案：

- 欢迎页负责品牌印象、价值表达和入口分发。
- 登录页负责完成手机号验证登录，不再承担欢迎语或冗余说明。
- “登录”和“注册”在用户界面上合并为同一动作：`手机号登录 / 注册`。
- 第三方登录只在支持平台展示。

这是对当前产品最稳妥的方案：既能提升转化，又不需要引入额外页面或改动后端接口。

## 信息架构

### 欢迎页职责

欢迎页只做三件事：

- 建立品牌第一印象
- 说明产品核心价值
- 将用户送入唯一主路径

欢迎页按钮结构调整为：

- 主按钮：`手机号登录 / 注册`
- 次按钮：`华为账号登录`
- 弱按钮：`先逛逛`

其中：

- 主按钮始终代表最通用、可预期的进入方式。
- 华为登录仅在 HarmonyOS 支持环境展示。
- “先逛逛”保留，但降低视觉权重，不与主动作竞争。

### 登录页职责

登录页专注于“完成登录”：

- 标题：`手机号登录 / 注册`
- 副标题：`未注册手机号验证后将自动创建账号`
- 主体字段：手机号、验证码、发送验证码、立即进入
- 协议：放在主按钮附近，作为前置约束
- 第三方登录：仅展示可用平台对应入口

这样用户不会再遇到“欢迎页分流，登录页合流”的认知冲突。

## 视觉方向

整体视觉采用“竞技感 + 金属质感 + 克制留白”的方向，延续当前金色品牌线索，但强化统一性和完成度。

### 欢迎页

- 使用更有比赛氛围的暗色背景图或暗纹背景，而不是普通铺底图。
- 顶部 logo 保留，但体积缩小，不再压制主标题和 CTA。
- 文案更聚焦行动感，例如：
  - 主标题：`每一杆，都值得被记录`
  - 副标题：`记录战绩、生成战报、找到真正旗鼓相当的对手`
- 底部操作区改为半浮层卡片，承载按钮与协议区，使页面更像“马上开始”的入口面板。

### 登录页

- 从“欢迎头部 + 表单”改为“轻头部 + 强操作区”的结构。
- logo 缩小，标题直接说明动作，不再重复欢迎语。
- 输入框采用高对比卡片式样式，聚焦态更明显。
- 主按钮使用品牌金渐变，发送验证码按钮为次级按钮，不抢夺主 CTA 视觉权重。
- 页面整体层次围绕“输入 -> 获取验证码 -> 进入”组织，减少视觉分散。

## 关键交互

### 1. 登录与注册合并表达

- 欢迎页不再区分“注册”和“登录”两个主入口。
- 登录页明确说明：未注册手机号验证后自动创建账号。
- 主按钮文案统一为 `手机号登录 / 注册` 或 `立即进入`，避免语义摇摆。

### 2. 协议前置

- 协议勾选放在主按钮上方。
- 未勾选时，主按钮和第三方登录按钮处于禁用态。
- 用户不再是点击后才被 toast 打断，而是在视觉上提前知道前置条件。
- 如果欢迎页已经勾选，登录页默认沿用同意状态，避免重复操作。

### 3. 表单即时反馈

- 手机号输入过程中进行轻校验。
- 手机号合法后，“获取验证码”按钮才可点击。
- 输入错误时优先在输入框下方展示提示，而不是完全依赖 toast。
- 验证码输入满 6 位后，可自动收起键盘，并让主按钮进入高可用状态。

### 4. 验证码反馈优化

- 发送成功后提供明确反馈：`验证码已发送，请注意查收`
- 需要时可补充脱敏手机号提示，例如 `已发送至 138****1234`
- 保留倒计时，但文案和样式更平静，避免干扰主流程

### 5. 第三方登录真实可用

- 仅在 HarmonyOS 环境展示华为登录按钮。
- 不支持的平台不展示该入口，而不是点击后再提示不可用。

### 6. 成功与失败反馈分层

- 表单校验错误：页面内提示
- 接口失败：toast 或轻提示
- 登录成功：立即跳转，在目标页轻提示“登录成功”
- 不再固定等待 1.5 秒，减少完成动作后的迟滞感

## 文案建议

### 欢迎页

- 主标题：`每一杆，都值得被记录`
- 副标题：`记录战绩、生成战报、找到真正旗鼓相当的对手`
- 主按钮：`手机号登录 / 注册`
- 次按钮：`华为账号登录`
- 弱按钮：`先逛逛`

### 登录页

- 标题：`手机号登录 / 注册`
- 副标题：`未注册手机号验证后将自动创建账号`
- 验证码按钮：`获取验证码`
- 主按钮：`立即进入`

## 落地范围

- `app/pages/welcome/index.vue`
- `app/pages/welcome/index.scss`
- `app/pages/login/login.vue`

如需减少页面文件内逻辑复杂度，可新增少量纯函数工具文件来承载：

- 入口文案与按钮可用性判断
- 平台能力判断
- 手机号与验证码的轻校验逻辑

## 验收标准

- 用户从欢迎页进入时，不再看到“注册 / 登录”双路径造成的歧义。
- 登录页在未勾选协议、手机号错误、验证码为空时，能在页面内给出明确反馈。
- 非 HarmonyOS 平台不再展示华为登录入口。
- 登录成功后立即完成跳转，不再有固定等待。
- 欢迎页与登录页在视觉上同属一个品牌系统，并比当前版本更有记忆点。

## 风险与取舍

- 如果欢迎页信息过多，可能削弱主 CTA，因此文案必须克制。
- 如果把协议约束做得过重，可能损失少量转化，因此需要用禁用态和弱提示替代强打断。
- 如果视觉过度强调品牌装饰，会影响输入效率，因此登录页仍应以表单可用性优先。

## 推荐结论

本次应将欢迎页与登录页视为一个完整的登录漏斗进行重构，而不是两个单独页面的美化。

最重要的变化不是“更炫”，而是三件事：

- 让入口路径更清楚
- 让登录动作更顺手
- 让品牌表达更完整

这会同时改善首登转化和页面质感，也是当前项目阶段最值得投入的一次入口优化。
