# PK 发起与接收入口平衡设计

## 背景

当前「我的」页中，用户发起 PK 的路径非常直接：

- 在状态卡中点击显眼的 `发起PK` 主按钮
- 选择比赛类型
- 打开扫码功能扫描对手二维码

但被扫描方的路径并不对等：

- 需要先意识到自己应该“出示二维码”
- 再在身份卡右上角点击一个没有明显说明的二维码 icon
- 打开弹层后，才看到“让对手扫描你的二维码进行匹配”的提示

这造成了明显的双边角色不对称：

- 发起方几乎零学习成本
- 被发起方需要先发现隐藏入口，再理解自己要做什么

对熟悉产品的老用户来说，这条路径还能被记住；但对新用户来说，这很容易形成“我知道要扫别人，但别人不知道去哪让我扫”的体验断点。

## 目标

- 让 PK 的两个参与角色都能在「我的」页上快速理解各自入口。
- 让“发起 PK”和“被对手扫描”成为一组并列、可见、可教学的动作。
- 在不改后端能力和二维码生成逻辑的前提下，显著降低新用户理解成本。
- 保持老用户已有二维码入口可用，避免突然失去熟悉路径。

## 非目标

本次设计不包含以下范围：

- 扫码逻辑重写
- 后端 PK 二维码数据结构改造
- 新增专门的 PK 引导页
- 改造首页、比赛页等其他位置的 PK 入口
- 用一次性新手教程替代信息架构修正

## 问题诊断

### 1. 可见性失衡

`发起PK` 作为主 CTA 被突出展示，而“出示自己的二维码”入口只存在于右上角 icon，视觉层级过低。

### 2. 角色不对称

产品当前只很好地支持了“我是发起方”的心智，没有同样支持“我是被挑战方”的心智。

### 3. 提示出现太晚

“让对手扫描你的二维码进行匹配”这句说明只在二维码弹层打开后才出现，用户在真正找到入口前得不到帮助。

### 4. 入口语义不明确

右上角二维码 icon 虽然在视觉上可能被部分用户理解，但对新用户来说，它更像“个人码 / 名片 / 分享码”，而不是“PK 配对入口”。

## 设计结论

本次采用“PK 双主动作并列”的方案：

- 主按钮：`发起PK`
- 次按钮：`出示PK码`

两者在同一操作区中并列展示，明确表达这是一组互补动作：

- `发起PK`：我去扫别人
- `出示PK码`：我给别人扫

这是比“加说明文字”更根本的修正，因为它改变的是入口架构，而不仅仅是提示文案。

## 信息架构

### 新的操作组

在「我的」页状态卡的主操作区中，将 PK 相关动作整理为一组：

- 主动作：`发起PK`
- 次动作：`出示PK码`

这组动作应处于用户最容易看到、最接近当前状态反馈的位置，而不是分散在一个主按钮和一个右上角 icon 中。

### 旧入口处理

右上角二维码 icon 暂时保留，但降级为辅助入口：

- 避免老用户突然找不到熟悉入口
- 逐步让主路径迁移到状态卡主操作区

换句话说，这次是“新增显性主入口”，不是“粗暴删除旧入口”。

## 交互设计

### 发起方

- 点击 `发起PK`
- 继续沿用现有流程：选择比赛类型 -> 打开扫码 -> 解析对手二维码 -> 建立对局

### 被发起方

- 点击 `出示PK码`
- 直接复用当前已有的“我的二维码”弹层
- 不新增新的二维码页面，也不改变二维码生成逻辑

### 二维码弹层优化

当前二维码弹层只写了“让对手扫描你的二维码进行匹配”，说明仍偏弱。

建议升级为：

- 标题：`出示PK码`
- 副说明：`让对手打开“发起PK”后扫描此码，即可开始匹配`
- 可选弱提示：`如果对手找不到入口，请让他前往“我的”页点击“发起PK”`

这样用户不仅知道“这是二维码”，还知道对方下一步应该怎么做。

## 文案建议

### 状态卡按钮

- 主按钮：`发起PK`
- 次按钮：`出示PK码`

### 二维码弹层

- 标题：`出示PK码`
- 说明：`让对手打开“发起PK”后扫描此码，即可开始匹配`

## 视觉建议

- `发起PK` 保持现有主按钮视觉地位。
- `出示PK码` 使用次级按钮样式，例如描边、浅底或低一层的品牌色填充。
- 两个按钮应在视觉上明显属于同一组，但不要都做成强主按钮，避免视线竞争。
- 如果状态卡中已有第二按钮位，可直接复用；如果没有，则在当前主按钮右侧新增对等布局。

## 落地范围

- `app/pages/user/index.vue`
- `app/pages/user/index.scss`

如需优化二维码弹层文案，也同步调整：

- `app/pages/user/index.vue`

## 验收标准

- 新用户进入「我的」页后，无需先理解右上角 icon，也能知道如何“给别人扫”。
- `发起PK` 与 `出示PK码` 的关系足够直观，用户能迅速理解这是两种互补动作。
- 点击 `出示PK码` 后，直接进入现有二维码弹层，不产生额外学习成本。
- 右上角旧入口仍可用，不会影响老用户习惯。

## 风险与取舍

- 如果两个按钮视觉同强，可能导致主次不清，因此 `出示PK码` 应保持次级视觉。
- 如果继续保留右上角 icon，短期内会有双入口；但这是可接受的过渡成本，换来的是更平滑的迁移。
- 如果只加提示而不改入口结构，问题仍会持续存在，因此本次不建议只做文案补丁。

## 推荐结论

这不是单纯的按钮命名优化，而是一次“补齐 PK 双边角色入口”的修正。

`发起PK` 和 `出示PK码` 并列后，用户会第一次真正理解：

- 我可以主动去扫别人
- 我也可以把码亮出来给别人扫

这会显著提升 PK 功能的可教性，尤其对新用户最有价值。
